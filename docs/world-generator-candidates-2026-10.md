# Кандидаты генерации из списка пользователя

Проверено 2026-10-14. Это **исследование исходников, не новая интеграция**.
Прочитаны GitHub metadata, README, рекурсивные деревья, лицензии выбранных
кандидатов и отдельные файлы API/генерации. Проекты не собирались, install.sh,
Gradle, CMake, серверы и чужие workflow не запускались. Производительность,
качество всех миров и заявления авторов о детерминизме экспериментально не проверены.
Текущий генератор MIR не заменён; метровый вид сверху, Azgaar, редактор,
планета, лобби и сохранения не менялись.

## Главный вывод

Здесь два разных выбора:

1. **Архитектура подгружаемых блоков.** Наиболее предметный источник из списка —
   API и core-addons Terra. Но это Java-платформа, преимущественно для Minecraft,
   а не готовый JS-модуль. Нужен ограниченный браузерный порт конкретных
   компонентов, а не копирование JAR в Vite.
2. **Реалистичное формирование материков.** Наиболее предметный исследовательский
   кандидат — RTWG: README заявляет симуляции воды, ветра, почвы, льда, тектоники
   и климата. Код использует C++/OpenGL и GLSL 4.30, лицензия GPLv3. Это отдельный
   существенный перенос, не включение готовой браузерной библиотеки.

Чанковый API сам по себе не создаёт реалистичных материков. Для MIR разумно
разделить глобальный макрорельеф и локальную детализацию/отрисовку. Замена
макрогенерации может изменить географию seed и контракт с редактором, поэтому
она не выполняется автоматически только из-за присланных ссылок.

«Не найдена лицензия» — результат проверки конкретного снимка, а не утверждение,
что разрешение невозможно получить. Публичный репозиторий доступен для чтения;
условия переноса основного кода нужно установить отдельно. GPL-проекты не
запрещены: при переносе и распространении необходимо выполнить их условия,
а не назвать полученный код MIT. Лицензии сторонних библиотек/ресурсов также
проверяются отдельно.

GitHub topic [world-generator](https://github.com/topics/world-generator) — каталог,
не девятый движок и не единая лицензия. Содержимое статьи
[Habr](https://habr.com/ru/companies/piter/articles/593237/) в этой проверке не
получено: домен вне доступного сетевого allowlist. Выводы о её реализации
не делаются.

## Важная особенность Terra

[README, Licensing](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/README.md#licensing)
прямо различает лицензии компонентов:

- Корневой [LICENSE](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/LICENSE): MIT.
- [common/implementation/LICENSE](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/implementation/LICENSE)
  и [platforms/LICENSE](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/platforms/LICENSE): GPLv3.
- Проверенный [NoiseChunkGenerator3D](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/chunk-generator-noise-3d/src/main/java/com/dfsek/terra/addons/chunkgenerator/generation/NoiseChunkGenerator3D.java)
  имеет MIT header и лицензию модуля core-addon. Однако его импорты Platform,
  ConfigPack, BlockState, SamplerProvider и др. показывают зависимости:
  этот файл не является самостоятельным JS-генератором.
- Проверенный [ChunkGenerator](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/api/src/main/java/com/dfsek/terra/api/world/chunk/generation/ChunkGenerator.java)
  содержит `generateChunkData(ProtoChunk, WorldProperties, BiomeProvider, chunkX, chunkZ)`,
  `getBlock(...)` и `getPalette(...)`. Это действительный API исходников,
  но наличие интерфейса не означает реализованный аналог в MIR.

Для выбранного порта нужен перечень конкретных классов, полные notices и
лицензионный аудит их зависимостей. Глобальная метка GitHub «MIT» недостаточна
для копирования всего дерева Terra.

## Как использовать присланное описание Generation / Population

Текст упоминает `org.spongepowered.api`, `WorldGeneratorModifier` и `PopulatorFactory`:
это описание API Sponge/Minecraft, а не документация текущего MIR или Terra.
Его формулировки «ещё не реализовано» относятся к состоянию описываемого API
на момент написания; их нельзя автоматически считать текущим состоянием Sponge.
Версия и дата самого фрагмента не установлены.

Полезные архитектурные принципы для браузерной карты:

1. **Глобальный слой:** материки, крупные горные пояса, базовый сток и биомы.
   Сейчас это Azgaar. Тектоника/общепланетарный сток не становятся независимыми
   локальными операциями только от разбиения на чанки.
2. **Generation:** чистое получение базовых колонок по world seed, версии,
   целочисленным мировым координатам и неизменяемому глобальному полю.
   Высоты не зависят от порядка загрузки или текущего LRU-кэша.
3. **Population:** необязательные локальные детали. Для объектов через границы
   нужны владелец объекта, стабильный идентификатор и согласованный halo.
   Одной проверки «соседи сгенерированы» недостаточно для независимости
   результата от порядка записей в соседние чанки.
4. **Размеры — параметры:** 16×256×16 из текста не являются обязательным
   контрактом MIR. Вершины материковой карты могут быть выше 256 м.
   В выбранном виде сверху достаточно колонок/разреженных данных; не требуется
   заполнять плотный массив воздуха и камня для всех Y.
5. **Смешанные биомы:** применять покрытие по колонке, а не копировать ограничение
   «один биом у `(x+16,0,z+16)` на весь чанк».
6. **Детерминизм деталей:** PRNG на координаты/идентификатор объекта, а не общий
   изменяемый `Math.random` при асинхронной подгрузке; отдельно тестировать
   порядок A→B против B→A, выгрузку/повтор и стыки.
7. **Память:** глобальное поле ограниченного разрешения + видимые локальные чанки
   и LOD; не буфер всех метров Земли. Уже работающий рендерер MIR использует
   64×64 LOD-тайлы и LRU128 — это блоки отображения, не автоматически чанки
   с игровыми populators, пещерами, деревьями и рудами.

Это предложение устройства, **не заявление, что новый Generation/Population API
уже написан**. Чтобы начать реализацию, требуется выбрать: ограниченный порт
чанкового ядра/детализации или замена глобального генератора с миграцией
источника редактора, рек, сохранений и лобби.
