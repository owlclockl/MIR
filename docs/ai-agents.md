## Распределение задач при наличии раннера с сабагентами

Координатор выдаёт исполнителям разные файлы, измеримый результат и только необходимый доступ. Остальные могут проводить read-only review. В отчёте нужны `файл:строка`, команда и результат, а не просто «исправлено». Перед объединением — проверка пересекающихся правок и регрессия. Производственные секреты, публикация и слияние веток остаются у владельца.

Скиллы (`frontend-design`, `webapp-testing`, `web-perf`, `workers-best-practices`, `durable-objects`) — чек-листы, не дополнительные модели. `npm run skills:check` сравнивает **только локальные файлы** с `skills-lock.json` без интернета. `npm run skills:upstream` сравнивает также исходные `SKILL.md` с GitHub через **общедоступный API без ключа** и сообщает расхождения; на 2026-10-13 нашёл три: `cloudflare`, `workers-best-practices`, `wrangler`. Возвращает код 1 при расхождении. `npm run skills` действительно обновляет копии (просмотрите дифф перед использованием). Общедоступный API имеет лимиты: при исчерпании повторите позже, не ищите чужой токен в сети.

## Что означает «открытый API-ключ»

API бывают **открытыми и без ключа** (например, публичный GitHub REST API для проверки скиллов), либо выдают **личный ключ** через зарегистрированный аккаунт, в том числе на бесплатном тарифе. Найденный в интернете готовый токен не становится «общедоступным» по согласию владельца: он может быть украден, быстро отозван или оплачивается чужим счётом. Общего легально опубликованного ключа для OpenAI/Anthropic/Cloudflare, который можно безопасно вписать в репозиторий, здесь нет. ИИ-провайдеры в игру не подключались.

GitHub API теперь можно использовать в работе агентов без регистрации через `npm run skills:upstream`. GitHub CLI в этой среде уже авторизован для операций с репозиторием; эти персональные учётные данные **не копируются** в файлы проекта. Для Cloudflare-деплоя `.github/workflows/deploy.yml` уже использует `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` из GitHub Actions Secrets, но здесь они не заданы: нельзя выдавать публичный API за права на чужой аккаунт. Создать/вписать личные ключи без учётной записи владельца нельзя.

Существующие настройки для владельца: `SAGES_ADMIN_KEY` задаётся в окружении локального хаба или интерактивно `npm run host:secret` как секрет Worker; `npm run host:secrets` показывает только имена. Если ключ ранее сменили в админ-панели, значение из данных хаба имеет приоритет. GitHub Actions Secrets настраиваются в настройках репозитория, не в PR. `VITE_SAGES_HUB` — публичный адрес, а не ключ. `npm run keys:status` показывает **только наличие** перечисленных переменных в текущем процессе, не подтверждает их валидность или наличие удалённых секретов; `npm run test:keys` проверяет отсутствие печати значений и правила игнорирования.

Локальные `.env*`, `.dev.vars*`, новые файлы `server/data/` игнорируются Git; **уже отслеживаемый** `server/data/sages-hub.json` этим из индекса и истории не удаляется. Ни один ключ нельзя записывать в `VITE_*`/`PUBLIC_*`: браузер получит его с клиентским бандлом. Реальные ключи не передавайте в чат, аргументах `--token`, логах и коммитах; если они уже попали туда — перевыпустите.
