# Замена основного генератора: разбор GitHub-проектов

Дата: 2026-10-14. В присланном списке четыре уникальных репозитория:
`spectrum-art/Continent-Generator` указан дважды.

## Что сейчас в The civilization of the sages

По запросу пользователя **удалён**, а не отключён, собственный основной движок
`src/gen/`, его колонковая модель и `src/game/world-map-view.js`, стили, кнопка
и тесты. Предыдущая доработка материков и облегчённой тектоники тоже удалена.
Не следует продолжать её под именем нового генератора.

До внедрения замены открывается уже встроенный Azgaar с [профилем материков земного масштаба](earth-scale-map.md). Планетарный режим
сохранён отдельно. Слоты, импорт/экспорт параметров, пользовательские данные
и синхронизация лобби сохранены. Слот хранит seed и размеры, а не снимок
удалённого мира; его прежняя процедурная поверхность больше не воспроизводится.

**Новый движок пока не выбран окончательно и не подключён.** Ни один из
рассмотренных ниже репозиториев не включён в зависимости или vendor The civilization of the sages.
Клоны для чтения находятся вне рабочего дерева. Разбор сделан по исходникам;
это не заявление, что чужие приложения собраны, проверены на телефоне или
полностью аудированы вместе с зависимостями.

## Четыре присланных проекта

### spectrum-art/Continent-Generator

[Репозиторий](https://github.com/spectrum-art/Continent-Generator),
snapshot `2f0636ea8370427976d323805cbc52e2e2792049`.

- Browser-native JavaScript, WebGPU/WGSL, настройка параметров через Rust/WASM.
- Маска суши отделена от плит и топографии. Плиты и их скорости задают
  сжатие, растяжение и сдвиг; Jump Flood распространяет ближайшие разломы,
  после чего собирается высота и отмывка. Рабочая сетка — 2048×1024.
- Изучены README, `src/main.js`, Rust-конфигурация, шейдеры маски, плит,
  напряжений, расстояний и высот. В дереве есть ранние версии проходов;
  порядок текущего исполнения следует смотреть в оркестрации, не по номерам
  старых файлов.
- Для The civilization of the sages это серьёзная интеграция нового GPU/WASM toolchain и поддержки
  устройств без WebGPU. Не готовая замена с климатом, поселениями и лобби.
- В проверенном snapshot не найдена лицензия, разрешающая перенос.

### ianjsikes/continent-generator

[Репозиторий](https://github.com/ianjsikes/continent-generator),
snapshot `e89c78d616ede542fdb6b27915bd067dc8816ae1`.

- Python, PIL и noise: базовый шум высот комбинируется с радиальным
  градиентом; затем вычисляются отдельные карты воды, ветра, температуры,
  дождей и биомов.
- Изучены README, `IslandGenerator.py`, `RadialGradient.py`, `HeightMapGen.py`,
  `Generators.py` и `Modifiers.py`.
- Подходит как источник алгоритмических подходов, но не как подключаемый
  браузерный движок: потребуются порт либо сервер/Python runtime. Сохранённые
  PNG не заменяют генерацию по пользовательскому seed.
- В проверенном snapshot не найдена лицензия, разрешающая перенос.

### blslade-neumont/procedural-continent-generator

[Репозиторий](https://github.com/blslade-neumont/procedural-continent-generator),
snapshot `3f6eaa9b1e526948b19aa8041f49c5cf3ca68b6a`.

- TypeScript, последовательность стадий: грубая случайная сетка →
  классификация соседей → повышение разрешения → новые проходы сглаживания.
- Изучены `default-generator.ts`, `generator-stage.ts`, `generator-controller.ts`.
  Контроллер использует раздельные буферы для прохода и отдаёт управление
  между порциями работы. В генерации есть `Math.random` без seed-контракта.
- Это прежде всего маска материков, не полноценная замена рельефа,
  гидрологии, климата и биомов. Нужно отделение от старого игрового engine.
- В проверенном snapshot не найдена лицензия, разрешающая перенос.

### Jimbly/worlds-continent-gen

[Репозиторий](https://github.com/Jimbly/worlds-continent-gen),
snapshot `95db43cd27c2c7f9333749440cbf628afb7250e0`.

- JavaScript/GLOV.js; гексагональная сетка и явные поля высоты, влажности,
  рек, уровня воды и классификации.
- Изучены README и стадии `src/client/continent_gen.js`: берега, заполнение
  морей, расстояния, озёра, рост речной сети, океанское дно, обработка склонов
  и выходные поля. Реки растут от берегов/озёр по собственной схеме приоритетов;
  это не алгоритм стока удалённого генератора The civilization of the sages.
- Экспорт в Worlds FRVR больше не работает по сообщению автора в README.
  Просмотр/генерация карты остаются отдельной частью приложения.
- README разрешает собственный код примера только для Worlds FRVR и связанных
  модов. MIT относится отдельно к GLOV.js / Worlds Mod API, не ко всему
  генератору. Переносить генератор в The civilization of the sages на основании MIT framework нельзя.

Публичность исходников не равна разрешению на включение в другой продукт.
Для дословного переноса первых трёх нужно найти/получить разрешение авторов;
для Jimbly — разрешение вне явно ограниченной области использования.

## Найденные альтернативы с явными лицензиями

### Рекомендуемый следующий кандидат: redblobgames/mapgen4

[Репозиторий](https://github.com/redblobgames/mapgen4),
snapshot `c1d8cb018a11a8b9e17d59233c36c176429d37eb`.

**Apache-2.0**, разрешено использование в собственных, в том числе коммерческих,
проектах с выполнением условий лицензии. Проверены LICENSE, README,
`package.json`, `build.sh`, `map.ts`, `worker.ts`, `render.ts`.

- JavaScript/TypeScript: отдельные алгоритмы рельефа, осадков, рек и геометрии;
  вычисления вынесены в worker, представление отделено от данных.
- По описанию автора оптимизирован для красивых интерактивных карт, не для
  физически точной Земли. Около 25 тысяч ячеек — ориентир оформления upstream,
  не измеренная здесь производительность The civilization of the sages.
- Его исходники действительно можно взять за основу нового движка, а не
  переписывать старый The civilization of the sages «по мотивам».
- **Ограничения:** README помечает проект как неподдерживаемый. Штатный
  `render.ts` требует WebGL2 и `EXT_color_buffer_float`; без проверки на
  Android/WebView обещать совместимость нельзя. Worker, point data и пути
  сборки требуют адаптации к Vite, offline-cache и автономному `sages.html`.
  Не обещает готовых поселений, государств, дорог или сферической планеты.
- Зависимости перечислены автором: dual-mesh/prng — Apache-2.0,
  delaunator/flatqueue — ISC, simplex-noise/Poisson sampling/gl-matrix — MIT.
  Перед включением нужно зафиксировать реальные версии и сохранить лицензии.

### Более простой вариант: redblobgames/mapgen2

[Репозиторий](https://github.com/redblobgames/mapgen2),
snapshot `f16f485a62510344afe13e9c6aa01f7fa25be17e`.

**Apache-2.0**. Проверены LICENSE, README.org, package.json и алгоритмические
модули `map.js`, `water.js`, `elevation.js`, `biomes.js`.

- Полигональная карта: Delaunay/dual-mesh → вода и океан → высоты и дренаж →
  речная сеть → влажность → температура → биомы. `WorldMap.calculate` отделён
  от отрисовки; есть собственные seed для дренажа и рек.
- Проще отделить CPU-данные и сделать обычный 2D-вид, если WebGL2 неприемлем.
- Тоже помечен неподдерживаемым. Базовая география ориентирована на островную
  карту 0…1000, не земную тектонику. Есть локальная сборка dual-mesh и импорты
  без расширений, требующие адаптации. Это не прямая npm-зависимость «поставил
  и всё работает» и не подключённый к The civilization of the sages движок.

### Другие направления

- [Mindwerks/worldengine](https://github.com/Mindwerks/worldengine): GitHub
  указывает **MIT**, основной язык Python. Кандидат для офлайн/серверной
  генерации; не готовый браузерный модуль. Полный аудит исходников не выполнен.
- [jeheydorn/nortantis](https://github.com/jeheydorn/nortantis): GitHub указывает
  **AGPL-3.0**, основной язык Java. Другой runtime и требования лицензии;
  не первый кандидат для текущего Vite/PWA. Полный аудит не выполнен.

## План внедрения отдельной задачей

1. Взять зафиксированный snapshot mapgen4 (либо mapgen2 для 2D-only), перенести
   реальные исходники с LICENSE, уведомлениями авторов и журналом адаптаций.
2. Собрать минимальный новый вид без модулей удалённого движка. Подключить
   seed/размеры слотов; не трактовать координаты upstream как физические метры.
3. Проверить детерминированность и связность данных, worker/dispose,
   потерю WebGL-контекста, неподдерживаемое устройство и реальный слабый телефон.
4. Включить worker и данные в web/offline и автономную сборку, исключить сетевые
   CDN-зависимости. Отдельно согласовать с лобби: нынешний поток кадров — Azgaar.
5. Только после этих проверок переключить основной маршрут на новый движок.
