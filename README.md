# The civilization of the sages

Минималистичное главное меню веб-игры: тёмная тема, острые углы, волосяные линии.

Это полноценное приложение (PWA): ставится на ПК и телефоны, работает офлайн.
Внутри — аккаунты, аватарки, друзья с заявками и код-приглашения. ПК может
быть «сервером» для друзей по Wi-Fi **и через интернет** — внешние серверы
для игры не нужны вообще; наружу выходит только временный туннель.

> История проекта — в [`CHANGELOG.md`](CHANGELOG.md), договорённости по стилю и
> правила работы — в [`AGENTS.md`](AGENTS.md). Меняете что-то — допишите запись в журнал.

## Установить как приложение

Откройте меню по **https** (туннель `--public` или GitHub Pages — см. ниже) и:

- **ПК (Chrome/Edge)** — кнопка «Установить» в адресной строке справа.
- **Android (Chrome)** — меню ⋮ → «Установить приложение» / «Добавить на
  главный экран».
- **iPhone/iPad (Safari)** — «Поделиться» → «На экран "Домой"».

После установки — отдельное окно без браузерной рамки, иконка с фирменным
знаком, запуск офлайн. Примечание: по голому http в локальной сети браузеры
установку не дают (техническое требование к service worker) — как сайт всё
равно работает.

## ПК как сервер для друзей

```bash
npm run share
```

Кроме раздачи меню, поднимается **хаб общих аккаунтов**: друзья, открывшие
сайт по адресу из той же Wi-Fi, автоматически подключаются к нему и видят
общие аккаунты, заявки, друзей и коды-приглашения. Регистрируйте каждого на
его устройстве — и добавляйте друг друга по имени или коду.

- Данные хаба — файл `data/mir-hub.json` на вашем ПК; удалите его, чтобы
  начать с чистого листа.
- Пароли по сети не ходят: хеш SHA-256 считается на устройстве игрока.
- Через хаб идёт и знакомство устройств для прямой связи (см. ниже).
- Хаб можно выключить: `node server/serve.mjs --no-hub` (тогда у каждого устройства
  свои локальные аккаунты, как раньше).

## Прямая связь между игроками (P2P)

Когда у двоих друзей открыто приложение, устройства соединяются
**напрямую**: сообщения идут с компьютера на компьютер, минуя любой
сервер. Ничего нажимать не нужно — связь поднимается сама, а в панели
друзей у такого игрока появляется значок звена цепи.

Открыв карточку друга, вы увидите состояние канала и переписку:

- **Напрямую** — всё как задумано, рядом показан пинг в миллисекундах.
- **Через хаб** — домашний роутер не пропустил прямой путь, поэтому
  сообщения идут через ПК-сервер, а попытки пробиться продолжаются
  в фоне. Связь при этом не теряется.
- **Соединяемся…** — идёт обмен адресами, обычно пара секунд.

Как это устроено: хаб передаёт только «визитки» соединения
(offer/answer/ICE, несколько килобайт), дальше трафик идёт мимо него.
Внешние серверы не используются вовсе — кроме публичных STUN, которые
лишь сообщают устройству его собственный внешний адрес.

### Без сервера вообще — по коду

Кнопка **«Прямое подключение по коду»** (в панели друзей и в профиле)
связывает два устройства без хаба и без интернета-посредника:

1. Один нажимает «Создать код приглашения» и отправляет код другу
   любым способом — мессенджером, почтой, запиской.
2. Второй открывает вкладку «Мне прислали код», вставляет его и
   получает **ответный код**.
3. Первый вставляет ответный код у себя — связь есть.

Так соединяются даже два `mir.html`, открытых с флешки.

## Аккаунты и друзья

Кнопка **«Войти»** в правом верхнем углу открывает окно входа/регистрации.

- **Аватарка** — в профиле (клик по имени в шапке): загрузка картинки с
  предпросмотром, кадрирование по центру до 96×96.
- **Добавить друга** — кнопка «+» в панели друзей: поиск по имени среди
  аккаунтов этого устройства. Заявки приходят блоком «Заявки» в ту же панель.
- **Код-приглашение** — в подвале панели и в профиле: передайте его другу,
  он введёт код у себя, и вы сразу станете друзьями друг у друга.

Проверить в одиночку: зарегистрируйте два аккаунта и переключайтесь между
ними через «Выйти» / «Войти». В двух вкладках тоже работает — список
синхронизируется сам. Если открыто по сети с `npm run share`, аккаунты
общие для всех, кто подключился (см. «ПК как сервер»).

## Запуск

```bash
npm install
npm run dev
```

### Windows — двойным кликом, без команд

- **`СБОРКА.bat`** — интерактивное меню сборки с выбором формата:
  - `[1]` **Веб-версия** (`dist/` и однофайловый `mir.html`).
  - `[2]` **Windows-установщик (`MIR-Setup.exe`)** — см. ниже.
  - `[3]` **Android-приложение (`MIR.apk`)** — см. ниже.
  - `[4]` **Всё сразу**. Если какой-то формат собрать не удалось, остальные
    всё равно соберутся, а в конце будет честный список «что получилось».
  Полученными файлами (`MIR-Setup.exe` и `MIR.apk`) можно делиться с друзьями, просто перекидывая их через Telegram, Discord, VK или флешку!

#### `MIR-Setup.exe` — Windows

Один файл: внутри лежит вся игра. Запускается тремя способами — окно
установщика, «просто поиграть без установки» и тихая установка
(`MIR-Setup.exe --install`, удаление — `--uninstall`).

- Ставится в `%LOCALAPPDATA%\Programs\MIR`, **права администратора не нужны**;
  делает ярлыки на рабочем столе и в «Пуске», регистрируется в «Установка и
  удаление программ».
- Игра открывается в отдельном окне браузера без адресной строки
  (Edge/Chrome/Brave/Vivaldi/Opera, что найдётся), а файлы отдаёт крошечный
  сервер на `http://127.0.0.1:47821`. Так работают и аккаунты, и офлайн-режим:
  по `file://` браузеры запрещают `localStorage` и service worker. Порт
  фиксированный — иначе при каждом запуске менялся бы адрес, а вместе с ним
  пропадали бы сохранённые аккаунты.
- **Для сборки** нужен компилятор C# из .NET Framework — он уже есть в
  Windows 10/11 (`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`).
  Если его нет, сборщик честно напишет об этом и не станет подсовывать
  нерабочий файл. Чтобы **запустить** готовый exe, ничего ставить не нужно.
- При первом запуске Windows SmartScreen покажет синее окно: «Подробнее» →
  «Выполнить в любом случае». Так ведёт себя любая программа без платной
  цифровой подписи (сертификат стоит десятки тысяч рублей в год).

#### `MIR.apk` — Android

- Android 5.0 и новее (minSdk 21, targetSdk 34 — требование Android 14+).
- Подпись своя, сразу v1 + v2: с Android 11 пакеты без подписи v2
  не устанавливаются вообще.
- Телефон спросит разрешение «установка из неизвестных источников» —
  это нормально для файла, который пришёл не из магазина.
- Внутри — WebView с игрой из `mir.html`, интернет не нужен.
- **`ИГРАТЬ-С-ДРУЗЬЯМИ.bat`** — запуск игры и сервера для друзей:
  - Выбор: игра по Wi-Fi (самый стабильный локальный режим) или через интернет (публичный туннель).
  - Автоматическое копирование ссылки в буфер обмена (Ctrl+V).
  - Встроенная автозащита: протокол HTTP/2, авто-переподключение при обрывах и сторожевой таймер.
- **`ЛОГИ-И-ДИАГНОСТИКА.bat`** — проверка связи, портов, DNS, статуса туннелей и логов в один клик. Автоматически сохраняет отчёт в `logs/diagnostic-report.txt` и копирует его в буфер обмена для отправки в чат.

## Диагностика и логи

## Показать друзьям

```bash
npm run share
```

Команда собирает продакшн-версию и поднимает сервер. В терминале появятся два адреса:

```
  На этом компьютере   http://localhost:4173/
  Для друзей в той же сети Wi-Fi:
                       http://192.168.1.42:4173/
```

Второй адрес и есть ссылка для друзей — **но только для тех, кто сидит в той же
сети Wi-Fi**. Пока команда работает, сайт доступен; закрыли терминал — ссылка умерла.

Полезное:

```bash
npm run serve                  # раздать уже собранный dist/, без пересборки
node server/serve.mjs . --port 8080   # другой каталог и порт
node server/serve.mjs --help          # все флаги
```

### Ссылка для друзей из интернета

Адрес `192.168.*` снаружи не открывается — нужен либо туннель, либо хостинг.

**Туннель — быстро, пока компьютер включён:**

```bash
npm run share:public
```

Поднимает временную `https://…loca.lt` ссылку через `npx localtunnel`.
Учтите: первому посетителю localtunnel показывает страницу с запросом пароля —
это ваш внешний IP, подсмотреть можно на <https://loca.lt/mytunnelpassword>.
Если туннель не поднимется, локальный сервер продолжит работать.

**GitHub Pages — постоянная ссылка, компьютер выключать можно:**

Репозиторий уже на GitHub, поэтому достаточно собрать и выложить `dist/`.
В настройках репозитория: *Settings → Pages → Source → GitHub Actions*,
затем добавить workflow, который делает `npm ci && npm run build` и публикует
`dist/`. Получится адрес вида `https://owlclockl.github.io/MIR/`.

### Если публичная ссылка не поднимается

Самая частая причина — **VPN или прокси с режимом TUN** (Clash, Surge,
StealthSurf, Radmin VPN и подобные). Они перехватывают разрешение имён и
отвечают поддельными адресами `198.18.x.x`, а запросы к DNS-серверу по
UDP:53 просто теряют.

Для сайтов это незаметно, но Cloudflare Tunnel при старте обязан получить
SRV-запись `_v2-origintunneld._tcp.argotunnel.com` — иначе он не знает, к
какому серверу подключаться, и падает с `Could not lookup srv records`
ещё до появления ссылки.

Поэтому перед публикацией сервер сам проверяет DNS и пишет, что именно
сломано. Что помогает:

1. Выключить VPN или прокси с TUN и запустить заново.
2. Прописать в свойствах сетевого адаптера DNS `1.1.1.1` и `8.8.8.8`.
3. Играть по локальной сети — пункт `[1]` в `ИГРАТЬ-С-ДРУЗЬЯМИ.bat`,
   интернет для этого не нужен вообще.

Если SRV-записи недоступны, сервер не тратит минуту на Cloudflare, а сразу
пробует localtunnel: ему хватает обычного разрешения имён, и он часто
работает даже через прокси. Подробный разбор — `ЛОГИ-И-ДИАГНОСТИКА.bat`
(раздел «4. ИНТЕРНЕТ И DNS»).

## Запуск одним файлом

Всё меню собрано в один самодостаточный файл `mir.html` (HTML + CSS + JS внутри).
Просто откройте его двойным кликом в браузере — ни Node, ни установки зависимостей
не нужно. Этот же файл удобно отправить другу в мессенджере.

Пересобрать после правок в `index.html` / `src/`:

```bash
npm run single   # или: node scripts/build-single.mjs
```
