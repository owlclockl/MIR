# The civilization of the sages

Минималистичное главное меню веб-игры: тёмная тема, острые углы, волосяные линии.

Это полноценное приложение (PWA): ставится на ПК и телефоны, работает офлайн.
Внутри — аккаунты, аватарки, друзья с заявками и код-приглашения.

Играть с друзьями можно тремя способами, и они не исключают друг друга:

| Способ | Когда подходит | Что нужно |
| --- | --- | --- |
| [**Бесплатный хостинг**](#игра-в-интернете-бесплатный-хостинг) | друзья где угодно, ссылка нужна всегда | одна команда `npm run host` |
| [ПК как сервер](#пк-как-сервер-для-друзей) | все в одной Wi-Fi | `npm run share`, компьютер включён |
| [Прямое подключение по коду](#без-сервера-вообще--по-коду) | сервера нет вообще | обмен кодами в мессенджере |

## Генератор мира

Кнопка **«Играть»** открывает самостоятельную полноэкранную студию MIR — экран
**слотов карт**: шесть слотов и две вкладки, **«Мастер»** и **«Игрок»**. У
каждой роли свои шесть слотов; слот заполняется картой (seed и параметры) и
хранится в браузере, превью слота — сама карта мира. Мастер создаёт карту в
пустом слоте, игрок входит в чужую по seed или файлу экспорта; заполненный
слот открывает карту в роли своей вкладки.

На карте два режима. **Мастер** получает полные функции: создание и настройка
мира, сохранение в слот, экспорт, снимок атласа и редактор Azgaar. **Игрок** —
урезанные: только просмотр атласа и разведданных. Встроенный генератор создаёт
процедурный voxel-мир: тот же seed воспроизводит биомы, высоты, названия, реки
и чанки; блоки создаются только рядом с камерой.

Стратегический атлас показывает слои **«Биомы»**, **«Рельеф»**, **«Высоты»** и
политические границы. Камеру можно панорамировать мышью как в RTS, приближать
колесом, перемещать клавишами **WASD / стрелками** (с **Shift** быстрее), а
щёлчком по глобальной карте перейти в другой сектор. На телефоне работает
перетаскивание.

В веб-версии и PWA верхняя панель студии открывает **Azgaar FMG** — полноценную
встроенную мастерскую Fantasy Map Generator: карта, биомы, культуры,
государства, города, слои, инструменты редактирования и экспорт. MIR передаёт
туда seed текущего мира; по умолчанию выбрана ночная карта с тёмно-зелёной
MIR-темой. Азгаара не грузим с внешнего сайта: исходники, лицензия MIT и
готовая сборка находятся в репозитории (`vendor/azgaar-fantasy-map-generator/`,
`public/fmg/`). Полный каталог входит в офлайн-кэш PWA; первая установка
загружает около 22 МиБ картографических ресурсов. Отдельный worker и Google
Analytics из upstream-сборки отключены.

Пересобрать vendored editor после изменений можно отдельно:
`npm run fmg:install && npm run fmg:build` (нужен Node 24+ для toolchain
Azgaar). Затем `npm run build`. Однофайловый `mir.html`, APK и EXE остаются
лёгкими автономными сборками: в них встроен собственный MIR-атлас, а крупный
Azgaar FMG доступен в web/PWA-версии. Принципы климата, генерации рельефа и
выбор источников описаны в [`docs/world-generation-references.md`](docs/world-generation-references.md).

> правила работы — в [`AGENTS.md`](AGENTS.md). Меняете что-то — допишите запись в журнал.

## Установить как приложение

Откройте меню по **https** (хостинг — см. «Игра в интернете», или туннель `--public`) и:

- **ПК (Chrome/Edge)** — кнопка «Установить» в адресной строке справа.
- **Android (Chrome)** — меню ⋮ → «Установить приложение» / «Добавить на
  главный экран».
- **iPhone/iPad (Safari)** — «Поделиться» → «На экран "Домой"».

После установки — отдельное окно без браузерной рамки, иконка с фирменным
знаком, запуск офлайн. Примечание: по голому http в локальной сети браузеры
установку не дают (техническое требование к service worker) — как сайт всё
равно работает.

## Игра в интернете: бесплатный хостинг

Туннель с домашнего ПК живёт ровно столько, сколько включён компьютер, и его
первым делом рубят VPN, прокси и провайдеры. Если ни один способ подключения
не заработал — выложите игру на хостинг: адрес будет постоянным, а компьютер
можно выключать.

```bash
npm run host:login   # один раз: вход в Cloudflare (бесплатно, без карты)
npm run host         # собрать и выложить
```

В конце второй команды печатается адрес вида
`https://mir.ВАШЕ-ИМЯ.workers.dev`. По нему открывается **и сама игра, и хаб
общих аккаунтов**: друзья заходят по ссылке, регистрируются, видят друг друга
в панели друзей и переписываются — независимо от того, кто где находится.
Windows без командной строки: **`ИГРА-В-ИНТЕРНЕТЕ.bat`**, пункт `[1]`.

#### Ключ панели админа на хостинге

Адрес на хостинге публичный, а заводской ключ (`owlananaslwo`) лежит в
открытом исходнике — панель после входа сама напомнит его сменить. Задать свой
ключ **до первого входа** можно секретом воркера — один раз, после первого
выкладывания:

```bash
npm run host:secret    # то же самое в длинной форме: npx wrangler secret put MIR_ADMIN_KEY
```

Команда спросит секрет и запишет его в воркер на Cloudflare. Введите любой
длинный текст — он станет паролем входа в панель (открыть панель: семь быстрых
касаний знака игры за 2,8 секунды, `Ctrl+Shift+Alt+A` или адрес с `#admin`).

А **сменить ключ в любой момент** можно прямо в панели: «Система» → «Ключ
администратора». Новый ключ запишется в данные хаба на Cloudflare и переживёт
перезапуски и автообновления. Какой ключ действует, решает сам хаб, в порядке
убывания: сменённый в панели → секрет воркера → заводской `owlananaslwo`.

- **Секрет переживает обновления.** Автодеплой из GitHub Actions (ниже) и
  повторный `npm run host` не трогают секреты воркера — после каждого изменения
  вводить ключ заново не нужно.
- **Проверить**, что секрет на месте: `npm run host:secrets`
  (или `npx wrangler secret list`) — в списке должно быть `MIR_ADMIN_KEY`.
- **Сменить** секрет: та же команда `npm run host:secret` — старое значение
  заменится новым (это не то же самое, что смена ключа в панели).

Что получается:

- **Ссылка работает всегда.** Ваш ПК больше ни при чём: ни туннеля, ни
  запущенного терминала.
- **https по умолчанию** — значит, игра ставится как приложение на телефон
  (Chrome: «Установить приложение», Safari: «На экран \"Домой\"»).
- **Аккаунты и друзья живут на хабе**, а не в браузере: один аккаунт на
  телефоне и на компьютере.
- **Хаб — основной маршрут**, через него сразу идут аккаунты, друзья и сообщения.
  WebRTC/P2P поднимается автоматически как вторичный канал и берёт на себя
  доставку только если хаб временно недоступен.
- **Платить не за что.** Бесплатный тариф Cloudflare Workers — 100 000
  запросов в сутки и 5 ГБ хранилища; компания друзей расходует единицы
  процентов от этого. Карта при регистрации не нужна.

### Автообновление хостинга после каждого изменения

В репозитории есть GitHub Actions workflow `.github/workflows/deploy.yml`.
После попадания изменений в ветку `main` он сам собирает проект и обновляет
Cloudflare Worker — повторно запускать `npm run host` на компьютере не нужно.
Секреты воркера (`MIR_ADMIN_KEY` из команды выше) при таком обновлении
**сохраняются** — задавать их в GitHub Secrets не требуется, они живут на
стороне Cloudflare. Один раз добавьте в **GitHub → Settings → Secrets and
variables → Actions**:

- `CLOUDFLARE_API_TOKEN` — API Token с правом **Edit Cloudflare Workers**;
- `CLOUDFLARE_ACCOUNT_ID` — идентификатор аккаунта из панели Cloudflare.

Запуск также доступен вручную: **Actions → Deploy MIR to Cloudflare → Run
workflow**.

### Как игра узнаёт, что вышла новая версия

После каждого выкладывания приложение само замечает новую сборку и говорит об
этом — ничего нажимать заранее не нужно:

- **Строка «Обновление» под шапкой** с кнопками **«Обновить сейчас»** и
  **«Позже»**. Пока она висит, игра продолжается как обычно: открытая страница
  не перезагружается из-за обновления. «Обновить сейчас» перезагружает меню на
  новой версии; «Позже» — новая версия включится при следующем запуске.
- **Уведомление в шторке телефона** — если в настройках включены
  «Уведомления на телефон». Переключатель выключен по умолчанию: браузер
  спрашивает разрешение один раз и навсегда, поэтому спрашивать его без
  действия игрока нельзя. Нажатие на уведомление открывает игру.
- **Проверка идёт сама**: при запуске, раз в пять минут по сети, при возврате
  в приложение (телефон игру не закрывает, а сворачивает) и когда появляется
  связь. Работает и там, где service worker недоступен, — на голом http по
  локальной сети хаб отвечает тем же файлом новостей. Если приложение
  установлено на Android (Chrome), система может будить его в фоне по своему
  расписанию — тогда уведомление придёт даже с закрытой игрой, но расписание
  задаёт система (обычно не чаще раза в 12 часов).
- **Копия с диска** (`mir.html`, `MIR.apk`, `MIR-Setup.exe`) обновляется
  целиком — новой сборкой; в настройках она так и пишет.

Обновляется всё вместе: и меню, и хаб. Аккаунты живут на хабе, поэтому после
обновления игрок остаётся в своём аккаунте.

Проверить, что всё поднялось:

```bash
npm run test:hub -- https://mir.ВАШЕ-ИМЯ.workers.dev
```

Скрипт прогоняет по живому адресу весь сценарий — регистрацию, вход, дружбу
по коду, аватарку, смену пароля и сигналинг P2P с длинным опросом — и пишет
по пунктам, что сработало.

### Как друзья подключаются к хабу

- **Проще всего — по ссылке.** Открыл адрес хостинга — уже на хабе.
- **Из офлайн-сборок** (`MIR.apk`, `MIR-Setup.exe`, `mir.html` с флешки) —
  кнопка **«Общий хаб»** внизу панели друзей: вставить адрес, «Подключиться».
  Это же окно показывает, где сейчас лежат аккаунты, и отключает хаб обратно.
- **Ссылкой с готовым адресом:** `https://ваш-сайт/?hub=https://mir.ваше-имя.workers.dev`
  — такой адрес запоминается сам.
- **Сборка с вшитым хабом** — чтобы друг вообще ничего не вводил:

  ```bash
  VITE_MIR_HUB=https://mir.ваше-имя.workers.dev npm run build:apk   # Linux/macOS
  set VITE_MIR_HUB=https://mir.ваше-имя.workers.dev && npm run build:apk   # Windows
  ```

  Полученный `MIR.apk` подключается к вашему хабу сразу после установки.

У каждого хаба свой список аккаунтов: при смене адреса нужно войти заново —
локальные аккаунты браузера при этом никуда не деваются.

### Если Cloudflare недоступен

Бывает, что провайдер или VPN режут именно этот хостинг. Логика хаба не
привязана к нему: ядро одно (`server/hub-core.mjs`), а адаптеры разные.
Тот же хаб поднимается на любом хостинге, где запускается Node:

```bash
npm ci && npm run build && npm start   # сервер слушает порт из переменной PORT
```

Так его берут Render, Koyeb, Northflank, обычная VPS. Честное предупреждение:
на бесплатных тарифах таких площадок диск не сохраняется между перезапусками —
аккаунты переживут сон сервиса, но не переустановку контейнера; каталог
`data/` в этом случае стоит положить на подключённый диск. У Cloudflare этой
беды нет: данные лежат в Durable Object.

## ПК как сервер для друзей

```bash
npm run share
```

Кроме раздачи меню, поднимается **хаб общих аккаунтов**: друзья, открывшие
сайт по адресу из той же Wi-Fi, автоматически подключаются к нему и видят
общие аккаунты, заявки, друзей и коды-приглашения. Регистрируйте каждого на
его устройстве — и добавляйте друг друга по имени или коду.

- Данные хаба — файл `data/mir-hub.json` на вашем ПК; удалите его, чтобы
  начать с чистого листа.
- Пароли по сети не ходят: хеш SHA-256 считается на устройстве игрока.
- Через хаб идёт и знакомство устройств для прямой связи (см. ниже).
- Хаб можно выключить: `node server/serve.mjs --no-hub` (тогда у каждого устройства
  свои локальные аккаунты, как раньше).

## Основное подключение через хаб, P2P — резерв

Сразу после запуска приложение подключается к общему хабу (если он доступен):
там находятся аккаунты и друзья, через него по умолчанию доставляются сообщения.
Это основной маршрут — одинаковый для разных устройств и домашних сетей.

Параллельно WebRTC/P2P автоматически пытается поднять прямой канал и остаётся
вторичным. Он используется для доставки, если хаб временно недоступен; если
прямой канал не пробился через NAT, на основном подключении через хаб это не
сказывается. В карточке друга показывается основной маршрут и состояние резерва.

Для сигналинга P2P хаб передаёт offer/answer/ICE (несколько килобайт). Внешние
сервисы не используются, кроме публичных STUN, которые сообщают устройству его
собственный внешний адрес.

### Резерв без хаба — по коду

Кнопка **«Прямое подключение по коду»** (в панели друзей и в профиле) — ручной
запасной вариант для случаев, когда общего хаба нет, например для двух
однофайловых `mir.html`. Она связывает два устройства напрямую:

1. Один нажимает «Создать код приглашения» и отправляет код другу
   любым способом — мессенджером, почтой, запиской.
2. Второй открывает вкладку «Мне прислали код», вставляет его и
   получает **ответный код**.
3. Первый вставляет ответный код у себя — связь есть.

Так соединяются даже два `mir.html`, открытых с флешки.

## Аккаунты и друзья

Кнопка **«Войти»** в правом верхнем углу открывает окно входа/регистрации.

- **Никнейм** — меняется в профиле без потери друзей, переписки и кода.
  Занятое имя приложение не даст сохранить.
- **Аватарка** — в профиле (клик по имени в шапке): редактор с перетаскиванием,
  масштабом, поворотом и точной настройкой кадра; сохраняется версия 192×192.
- **Настройки** — шестерёнка слева вверху: звуки, громкость, анимации,
  состояние обновлений (кнопка «Проверить»/«Обновить» по обстановке) и
  переключатель **«Уведомления на телефон»** — уведомления в шторке о новой
  версии. Звуки игрового меню — 13 откликов из открытой библиотеки **UI SFX**
  (набор «Arcade», CC0): клики, окна, переходы, переключатели, подключение и
  отдельный сигнал тайного входа. Лицензия и происхождение — в
  `src/assets/sounds/LICENSE.txt`; сменить набор можно командой:
  `npm run sounds -- glass`.
- **Добавить друга** — кнопка «+» в панели друзей: поиск по имени среди
  аккаунтов этого устройства. Заявки приходят блоком «Заявки» в ту же панель.
- **Код-приглашение** — в подвале панели и в профиле: передайте его другу,
  он введёт код у себя, и вы сразу станете друзьями друг у друга.
- **Общий хаб** — кнопка в подвале панели друзей и в профиле: показывает, где
  сейчас лежат аккаунты (этот браузер или адрес хаба), подключает к хабу по
  адресу и отключает обратно.

**Вход переживает перезагрузку.** Обновление страницы (F5), закрытие и
повторное открытие вкладки, перезапуск приложения — всё это «вышел из меню»,
а не «вышел из аккаунта»: сессия остаётся, и после загрузки вы снова в своём
аккаунте. Токен устройства отзывает только кнопка **«Выйти»** — и только у
этого устройства: на телефоне и на ПК входы живут своей жизнью.

Если хаб не ответил в первые секунды (холодный воркер на хостинге, спящий
туннель), страница не выкидывает из аккаунта: меню покажет, что связи нет, а
приложение само повторит подключение и вернёт вас в аккаунт, как только хаб
отвечит. Единственное исключение — браузер вообще не разрешает сохранять
данные (например, `mir.html` открыт файлом в Firefox): тогда окно входа прямо
предупредит, что аккаунт не переживёт перезагрузку, и предложит открыть игру
по ссылке.

Проверить в одиночку: зарегистрируйте два аккаунта и переключайтесь между
ними через «Выйти» / «Войти». В двух вкладках тоже работает — список
синхронизируется сам. Если открыто по сети с `npm run share`, аккаунты
общие для всех, кто подключился (см. «ПК как сервер»).

## Скрытая панель админа

Служебный раздел для владельца игры: аккаунты, пароли, дружба и состояние
хаба. В меню его нет — он открывается тем, кто знает, куда нажать.

**Как войти** — любым из трёх способов:

| Способ | Кому удобно |
| --- | --- |
| **Семь быстрых касаний знака игры** (слева вверху, за 2,8 секунды) | всем, и особенно с телефона |
| **`Ctrl` + `Shift` + `Alt` + `A`** | с клавиатурой |
| **Адрес с `#admin`** — например `…/index.html#admin` или `mir.html#admin` | когда ссылка уже под рукой |

Дальше окно спросит **ключ администратора**. Заводской ключ везде один —
`owlananaslwo` (он в открытом исходнике, поэтому панель сразу напоминает его
сменить):

- **аккаунты этого браузера** (`mir.html`, exe, APK) — заводской ключ.
  Смените его в панели: «Система» → «Ключ администратора»;
- **хаб на своём ПК** (`npm run share`, `ИГРАТЬ-С-ДРУЗЬЯМИ.bat`) — заводской
  ключ, если владелец не задал свой: `MIR_ADMIN_KEY=свой-ключ node server/serve.mjs`.
  Действующий ключ печатается при запуске сервера;
- **хаб на бесплатном хостинге** — заводской ключ, если владелец не задал
  секрет `npx wrangler secret put MIR_ADMIN_KEY` (см. «Игра в интернете»).

**Смена ключа из панели работает везде, и на хабе тоже**: новый ключ
записывается в данные хаба (файл `data/mir-hub.json` на ПК, хранилище Durable
Object на хостинге), переживает перезапуск и действует для всех устройств
владельца. Кнопка «Вернуть заводской» возвращает `owlananaslwo` — запасной
вход, если свой ключ забыт. Введённый ключ живёт только в памяти открытой
вкладки: перезагрузка страницы снова спросит его.

### Что умеет панель

Вкладок пять: **Обзор**, **Игроки**, **Заявки**, **Журнал**, **Система**.
Данные панель показывает снимком — при входе и по кнопке «Обновить»; сама по
таймеру она ничего не подгружает, поэтому на экране ровно то, что вы
запросили.

**Обзор** — сводка на одном экране: сколько всего аккаунтов, кто в сети,
сколько зарегистрировалось за сутки и сколько заходило, сколько аккаунтов
заблокировано, сколько заявок. Ниже — шесть последних событий журнала и
переключатель регистрации. Пока действует заводской ключ, здесь же висит
предупреждение о нём.

**Игроки** — список аккаунтов (хаба или этого браузера в офлайн-режиме).
Поиск ищет по имени, id и коду-приглашению. Фильтры: все, в сети, офлайн,
заблокированные; порядок — по имени, по последнему визиту или по дате
регистрации. В строке видно, кто в сети, сколько у него друзей, заявок и
когда он заходил. По строке открывается **карточка игрока**:

- переименование (3–16 символов, имя не занято);
- сброс пароля — задаёте новый, по сети идёт только хеш
  `SHA-256(salt:пароль)`, все старые входы игрока отзываются;
- **блокировка** — с причиной и на срок (час, сутки, неделя, 30 дней или
  навсегда). Заблокированному закрыт вход: он видит причину, а его устройства
  отключаются сразу. Блокировка снимается одной кнопкой, аккаунт при этом
  цел — удалять его для этого не нужно;
- копирование id и кода-приглашения одной кнопкой;
- новый код-приглашение (старый перестаёт работать);
- удаление аватарки;
- отключение устройств — все сессии игрока отзываются, он выходит из сети;
- разрыв дружбы — с выбранным игроком или сразу со всеми;
- удаление аккаунта — вместе со всеми его заявками и дружбой.

Там же видны заявки этого игрока — их можно удалить, не открывая вкладку
«Заявки».

**Заявки** — входящие и исходящие заявки в друзья: можно отклонить, не
дожидаясь ответа игрока. Имена в строке открывают карточку игрока.

**Журнал** — короткая память хаба: регистрации, входы, смена ника и пароля,
дружба, коды-приглашения и каждое действие из самой панели. Записей — до 300,
свежие сверху; фильтр оставляет «Всё», только игроков или только панель.
Журнал можно очистить (это тоже попадает в журнал — чтобы «пусто» не
выглядывало как «ничего не было»). Пароли и ключи в журнал не попадают: только
имена, id и повод.

**Система** — диагностика и управление:

- статистика: режим данных (хаб или только этот браузер), адрес хаба,
  аккаунтов всего, в сети, новых за сутки и за неделю, заходивших за сутки,
  заблокированных, заявок, дружб, аватарок, записей в журнале, объём данных;
- **настройки хаба**: открыть или закрыть регистрацию новых аккаунтов — пока
  закрыта, хаб отвечает регистрации отказом (в локальном режиме переключатель
  действует на аккаунты этого браузера);
- состояние: активен ли service worker (автообновление), есть ли доступная
  версия и когда её проверяли, доступен ли WebRTC для прямой связи, версия
  игры;
- выгрузка копии данных хаба одним JSON-файлом — вместе с журналом и
  настройками;
- «Заблокировать панель» — выход из панели, при следующем входе ключ спросят снова;
- **ключ администратора**: смена (свой ключ, минимум 6 символов, заводской
  взять нельзя) и «Вернуть заводской»;
- очистка локальных аккаунтов этого браузера — с подтверждением, на хабе
  ничего не меняется.

Панель устроена так, чтобы ею не злоупотребили: заводской ключ публичный,
поэтому панель показывает предупреждение, пока ключ не сменён, а на ПК-хабе
с публичной ссылкой сервер предупреждает об этом при запуске. Всё, что делает
панель, она делает настоящими маршрутами хаба (`/api/admin/*`) — те же
правила действуют и на ПК, и на хостинге, потому что живут в одном файле
`server/hub-core.mjs`.

### Windows — двойным кликом, без команд

- **`СБОРКА.bat`** — интерактивное меню сборки с выбором формата:
  - `[1]` **Веб-версия** (`dist/` и однофайловый `mir.html`).
  - `[2]` **Windows-установщик (`MIR-Setup.exe`)** — см. ниже.
  - `[3]` **Android-приложение (`MIR.apk`)** — см. ниже.
  - `[4]` **Всё сразу**. Если какой-то формат собрать не удалось, остальные
    всё равно соберутся, а в конце будет честный список «что получилось».
  Полученными файлами (`MIR-Setup.exe` и `MIR.apk`) можно делиться с друзьями, просто перекидывая их через Telegram, Discord, VK или флешку!

#### `MIR-Setup.exe` — Windows

Один файл: внутри лежит вся игра. Запускается тремя способами — окно
установщика, «просто поиграть без установки» и тихая установка
(`MIR-Setup.exe --install`, удаление — `--uninstall`).

- Ставится в `%LOCALAPPDATA%\Programs\MIR`, **права администратора не нужны**;
  делает ярлыки на рабочем столе и в «Пуске», регистрируется в «Установка и
  удаление программ».
- Игра открывается в отдельном окне браузера без адресной строки
  (Edge/Chrome/Brave/Vivaldi/Opera, что найдётся), а файлы отдаёт крошечный
  сервер на `http://127.0.0.1:47821`. Так работают и аккаунты, и офлайн-режим:
  по `file://` браузеры запрещают `localStorage` и service worker. Порт
  фиксированный — иначе при каждом запуске менялся бы адрес, а вместе с ним
  пропадали бы сохранённые аккаунты.
- **Для сборки** нужен компилятор C# из .NET Framework — он уже есть в
  Windows 10/11 (`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`).
  Если его нет, сборщик честно напишет об этом и не станет подсовывать
  нерабочий файл. Чтобы **запустить** готовый exe, ничего ставить не нужно.
- При первом запуске Windows SmartScreen покажет синее окно: «Подробнее» →
  «Выполнить в любом случае». Так ведёт себя любая программа без платной
  цифровой подписи (сертификат стоит десятки тысяч рублей в год).

#### `MIR.apk` — Android

- Android 5.0 и новее (minSdk 21, targetSdk 34 — требование Android 14+).
- Подпись своя, сразу v1 + v2: с Android 11 пакеты без подписи v2
  не устанавливаются вообще.
- Телефон спросит разрешение «установка из неизвестных источников» —
  это нормально для файла, который пришёл не из магазина.
- Внутри — WebView с игрой из `mir.html`, интернет не нужен.
- **Аватарка добавляется прямо с телефона.** WebView не умеет открывать
  выбор файла сам — это делает приложение, и оно делает: системный выбор
  («Файлы», «Фото», облачные диски, камера) открывается по кнопке
  «Добавить аватарку», разрешения на хранилище не спрашивает.
- **Если что-то идёт не так, это видно, а не угадывается:**
  - каждая сборка пишет протокол в `logs/apk-build.log` (размеры, смещения,
    хеши, все проверки и то, как их провал выглядит на телефоне);
  - готовый файл можно разобрать в любой момент: `npm run apk:doctor`
    (отчёт — в `logs/apk-report.txt` и в буфере обмена);
  - падение приложения показывается **прямо на экране телефона** полным
    стеком, который можно выделить и скопировать;
  - если WebView запустился, но меню не нарисовалось, через 6 секунд
    появится отчёт о том, чего не хватило (обычно — старый WebView);
  - в системном журнале телефона всё лежит под тегом `MIR`:
    `adb logcat -s MIR:V AndroidRuntime:E PackageManager:I`.
- **`ИГРА-В-ИНТЕРНЕТЕ.bat`** — постоянная ссылка на бесплатном хостинге:
  - `[1]` выложить игру и хаб (сборка и публикация одной кнопкой);
  - `[2]` вход в Cloudflare — нужен один раз, браузер откроется сам;
  - `[3]` проверить уже выложенный хаб по адресу (`npm run test:hub`);
  - `[4]` живой поток логов Cloudflare Worker (параметры — в `wrangler.toml`).
- **`ИГРАТЬ-С-ДРУЗЬЯМИ.bat`** — запуск игры и сервера для друзей:
  - Выбор: игра по Wi-Fi (самый стабильный локальный режим) или через интернет (публичный туннель).
  - Автоматическое копирование ссылки в буфер обмена (Ctrl+V).
  - Встроенная автозащита: протокол HTTP/2, авто-переподключение при обрывах и сторожевой таймер.
- **`ЛОГИ-И-ДИАГНОСТИКА.bat`** — проверка связи, портов, DNS, статуса туннелей и логов в один клик. Автоматически сохраняет отчёт в `logs/diagnostic-report.txt` и копирует его в буфер обмена для отправки в чат.

## Диагностика и логи

```bash
npm run doctor      # самодиагностика системы, портов и сети
npm run apk:doctor  # разбор собранного MIR.apk: что внутри и что не так
npm run logs        # показать журнал событий сервера
npm run test:hub -- https://адрес   # полный разбор живого хаба по его адресу
npm run test:worker # адаптер хостинга (Cloudflare) без сети: хранение и перезапуск
npm run test:ui     # собранный mir.html в jsdom: окна, кнопки, подключение к хабу
npm run test:avatar # выбор аватарки в jsdom: поле выбора файла, выбор, отмена
npm run host:logs   # поток логов Cloudflare Worker (см. observability в wrangler.toml)
```

Что куда пишется:

| Файл | Что внутри |
| --- | --- |
| `logs/mir-server.log` | события и ошибки сервера |
| `logs/diagnostic-report.txt` | отчёт `npm run doctor` (сеть, порты, DNS) |
| `logs/apk-build.log` | протокол сборки APK: каждый шаг, размер, хеш, проверка |
| `logs/apk-doctor.log` | полный разбор готового APK по байтам |
| `logs/apk-report.txt` | короткий отчёт об APK — его удобно переслать |

Предыдущий протокол не затирается: он остаётся рядом с суффиксом `.prev.log`.
`npm run apk:doctor -- --verbose` печатает весь разбор прямо в консоль, а
`npm run apk:doctor -- путь\к\файлу.apk` разбирает любой другой пакет.

## Команды сборщика

```bash
npm run build        # веб-версия в dist/ (её раздаёт сервер, хаб и .exe)
```

версии и хеша содержимого, поэтому старый кэш не может «залипнуть» у игроков.

### Ссылка для друзей из интернета

Адрес `192.168.*` снаружи не открывается — нужен либо туннель, либо хостинг.

**Туннель — быстро, пока компьютер включён:**

```bash
npm run share:public
```

Поднимает временную `https://…loca.lt` ссылку через `npx localtunnel`.
Учтите: первому посетителю localtunnel показывает страницу с запросом пароля —
это ваш внешний IP, подсмотреть можно на <https://loca.lt/mytunnelpassword>.
Если туннель не поднимется, локальный сервер продолжит работать.

**Хостинг — постоянная ссылка, компьютер выключать можно:**

`npm run host` выкладывает игру вместе с хабом и выдаёт адрес, который
работает всегда. Подробности — в разделе
[«Игра в интернете: бесплатный хостинг»](#игра-в-интернете-бесплатный-хостинг).
Туннели ниже остаются для случая «надо прямо сейчас и ненадолго».

### Если публичная ссылка не поднимается

Самая частая причина — **VPN или прокси с режимом TUN** (Clash, Surge,
StealthSurf, Radmin VPN и подобные). Они перехватывают разрешение имён и
отвечают поддельными адресами `198.18.x.x`, а запросы к DNS-серверу по
UDP:53 просто теряют.

Для сайтов это незаметно, но Cloudflare Tunnel при старте обязан получить
SRV-запись `_v2-origintunneld._tcp.argotunnel.com` — иначе он не знает, к
какому серверу подключаться, и падает с `Could not lookup srv records`
ещё до появления ссылки.

Поэтому перед публикацией сервер сам проверяет DNS и пишет, что именно
сломано. Что помогает:

1. Выключить VPN или прокси с TUN и запустить заново.
2. Прописать в свойствах сетевого адаптера DNS `1.1.1.1` и `8.8.8.8`.
3. Играть по локальной сети — пункт `[1]` в `ИГРАТЬ-С-ДРУЗЬЯМИ.bat`,
   интернет для этого не нужен вообще.

Если SRV-записи недоступны, сервер не тратит минуту на Cloudflare, а сразу
пробует localtunnel: ему хватает обычного разрешения имён, и он часто
работает даже через прокси. Подробный разбор — `ЛОГИ-И-ДИАГНОСТИКА.bat`
(раздел «4. ИНТЕРНЕТ И DNS»).

## Запуск одним файлом

Всё меню собрано в один самодостаточный файл `mir.html` (HTML + CSS + JS внутри).
Просто откройте его двойным кликом в браузере — ни Node, ни установки зависимостей

Пересобрать после правок в `index.html` / `src/`:

```bash
npm run build    # обновит dist/ (папку сайта) и проверит сборку

```

Внутри `mir.html` лежит всё, кроме шрифтов: код, стили, звуки и значок

системный, но меню продолжит работать.
