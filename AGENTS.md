# Инструкции для ИИ-агентов

Этот файл читается автоматически перед работой с репозиторием. Человеку он тоже
не помешает: ниже договорённости, которые держат проект в одном стиле.

---

## Главное правило: журнал изменений

**`CHANGELOG.md` — источник правды по истории проекта.**

1. **Перед работой** — прочитайте `CHANGELOG.md` целиком. Там записано, что уже
   сделано, что сознательно решено не делать и какие вопросы остались открытыми.
   Это дешевле, чем заново разбирать историю коммитов.
2. **После работы** — допишите запись в начало списка (новые сверху). Без записи
   задача не считается закрытой.

Формат записи:

```markdown
## 2026-10-05 — краткая суть одной строкой

**Что сделано**
- по пунктам, человеческим языком, без пересказа диффа

**Почему**
- причина правки: что было не так

**Решено не делать**
- что сознательно не тронули и почему (чтобы следующий не переделывал)
```

Разделы «Почему» и «Решено не делать» важнее списка файлов: диff виден в git,
а намерение — нет.

## Что это за проект

Главное меню веб-игры **The civilization of the sages** с системой аккаунтов:
регистрация/вход, аватарки, друзья с заявками, код-приглашения. Это PWA —
ставится на ПК и телефоны как приложение и работает офлайн. Два режима
данных: локальный (`localStorage` браузера) и общий хаб. Хаб живёт либо на
ПК игрока (`server/serve.mjs` поднимает `/api/*`, данные в
`data/mir-hub.json`), либо на бесплатном хостинге (`hosting/cloudflare/`,
данные в Durable Object) — логика у них общая, `server/hub-core.mjs`.
Выбор адреса — в `initBackend()`: ссылка `?hub=`, сохранённый адрес, вшитый
при сборке `VITE_MIR_HUB`, адрес страницы; не ответил никто — локально.
Поверх этого — прямая связь игроков (`src/data/p2p.js`): устройства
соединяются по WebRTC напрямую, хаб только знакомит их друг с другом.
Кнопки «Играть» и «Настройки» по-прежнему без логики: про них не просили.

Правило простое: `src/data` знает про данные и сеть, `src/ui` — про
разметку и мелочи интерфейса, `src/main.js` их склеивает. Скрипты и
сервер лежат по папкам и никогда не зависят от рабочего каталога —
для этого есть `scripts/lib/root.mjs`.

## Команды

```bash
npm install
npm run dev      # разработка, localhost:5173
npm run build    # продакшн-сборка в dist/
npm run single   # пересобрать mir.html
npm run share    # собрать и раздать по сети
npm run serve    # раздать уже собранный dist/
npm run build:exe  # Windows-установщик (нужен csc из .NET Framework)
npm run build:apk  # Android-приложение
npm run apk:doctor # разбор готового MIR.apk (можно указать путь и --verbose)
npm run build:all  # всё сразу
npm run doctor     # диагностика сети и туннелей
npm run host       # выложить игру и хаб на бесплатный хостинг Cloudflare
npm run host:dev   # тот же хостинг локально (workerd), без выкладывания
npm run test:p2p   # проверка прямой связи: два клиента, живой WebRTC
npm run test:hub   # проверка хаба по адресу: аккаунты, друзья, сигналинг
npm run test:ui    # смоук-проверка mir.html в jsdom: окна, кнопки, хаб
```

`test:hub` принимает адрес: `npm run test:hub -- https://mir.имя.workers.dev`
(без адреса проверяет `http://127.0.0.1:4173`). Гонять его нужно и по хабу
на ПК, и по выложенному — они обязаны вести себя одинаково.

`test:p2p` требует запущенного `npm run share` на порту 4300 и
одноразовой установки полифила WebRTC для Node:
`npm i --no-save node-datachannel`. `test:ui` — живого хаба на
`127.0.0.1:8787` (`npm run host:dev`), свежего `mir.html` и
`npm i --no-save jsdom`. В обычной сборке этих зависимостей нет —
скрипты нужны только разработчику.

## Договорённости

**Стиль.** Тёмная тема, острые углы (никаких скруглений), волосяные линии
`rgba(255,255,255,.08)`, разрядка в подписях капсом, один акцентный цвет
`--accent`. Шрифты Inter (интерфейс) и Manrope (заголовки, логотип).
Новые значения цвета и отступов — через переменные в `:root`, а не числами по месту.

**Никаких заглушек.** Функциональность добавляется только по явной просьбе
владельца — но тогда она обязана быть настоящей и доведённой до конца
(сейчас это аккаунты, аватарки и друзья). Никаких «скоро будет доступно»,
`alert` и ссылок в никуда. Кнопки, про которые не просили («Играть»,
«Настройки»), остаются честно бездейственными.

**Логика хаба — только в `hub-core.mjs`.** Адаптеры (`server/hub.mjs` для
ПК, `hosting/cloudflare/worker.js` для хостинга) знают ровно две вещи: как
прочитать запрос и куда сложить данные. Ни одного правила игры — имён,
паролей, дружбы, лимитов — в адаптерах быть не должно, иначе ПК и хостинг
разойдутся молча. Ядро живёт на голых веб-API (`fetch`, `crypto`,
`setTimeout`): `node:*` в нём запрещён — в воркере таких модулей нет.
Меняете ядро — прогоните `npm run test:hub` по обоим адаптерам.

**Прямая связь — в `p2p.js`.** Весь WebRTC (соединения, повторы,
сердцебиение, коды подключения) живёт только там; `main.js` лишь
спрашивает статус и рисует. Хаб в сигналинге передаёт исключительно
offer/answer/ICE и запасные сообщения — никакой игровой логики на
сервере. Меняете набор сигналов — поправьте и `hub.mjs`
(`/api/p2p/*`), и `p2p.js`: они обязаны понимать одно и то же.

**Логика — в `store.js`.** Всё состояние читайте и меняйте только через его
функции; прямые обращения к `localStorage` из `main.js` запрещены. Пароли —
только хешированные (SHA-256 + соль), в открытом виде не храним, не логируем
и по сети не гоняем (на хаб уходит только хеш). Дублирующая бизнес-логика
хаба в `hub.mjs` должна зеркалить локальный бэкенд `store.js` — меняете
правило в одном месте, меняйте и в другом.

**Сборка обязана объяснять свои ошибки.** Любой сборщик пишет полный
протокол через `scripts/lib/log.mjs` в `logs/<имя>.log`: шаги, размеры,
смещения, хеши и каждую проверку. Проверка формулируется так, чтобы при
провале было видно следствие («Android 11+ отвергнет пакет:
INSTALL_PARSE_FAILED_RESOURCES_ARSC_COMPRESSED»), а не только факт
несовпадения. Новую проверку добавляете — добавляйте и объяснение в поле
`fail`. Самопроверка идёт по **прочитанному с диска файлу**
(`scripts/lib/apk-read.mjs`), а не по переменным в памяти: иначе сборщик
проверяет собственные намерения. Строгие разборщики (`crypto.X509Certificate`,
`openssl`) обязательны там, где на телефоне работает BoringSSL — нестрогие
библиотеки пропускают ошибки, из-за которых Android отказывает в установке.

**Ошибка на телефоне должна быть видна с телефона.** В APK зашиты два
независимых способа: активность ловит исключение в `onCreate` и печатает стек
на экран (плюс `Log.e` с тегом `MIR`), а в страницу вставляется экранный
журнал из `scripts/lib/web-diagnostics.mjs`. Тот журнал пишется на ES5 без
стрелочных функций и шаблонных строк — он обязан выполниться в старом
WebView, который не смог разобрать основной бандл; иначе самый частый случай
(«телефон старый») так и останется чёрным экраном.

**Service worker.** Кэширует всё, кроме `/api/*`. Меняете стратегию кэша —
поднимите имя `CACHE` в `public/sw.js`, иначе у пользователей зависнет
старая версия.

**Артефакты пересобирать.** После правок в `index.html` или `src/` обязательно
`npm run single`, иначе `mir.html` разойдётся с исходниками. Если поменялась
раскладка — обновите `preview.svg`.

**Тексты.** Интерфейс русский, название игры английское:
«The civilization of the sages». В шапке и заголовке оно разбито на две строки
(`The civilization` / `of the sages`) — так длинное имя не ломает сетку.

**Адаптив.** Проверяйте диапазон 320–2560px. Контрольные точки: 1180 (сужается
панель друзей), 1000 (прячется текст профиля), 860 (панель уходит вниз лентой),
680 (прячется название в шапке), `max-height: 620px` (мельчает заголовок).

**Доступность.** У каждой кнопки доступное имя, видимый фокус, логичный порядок
табуляции, ориентиры `header/nav/main/aside/footer`, одна `h1` на страницу.
