## Главное правило: журнал изменений

**`CHANGELOG.md` — источник правды по истории проекта.**

1. **Перед работой** — прочитайте `CHANGELOG.md` целиком. Там записано, что уже
   сделано, что сознательно решено не делать и какие вопросы остались открытыми.
   Это дешевле, чем заново разбирать историю коммитов.
2. **После работы** — допишите запись в начало списка (новые сверху). Без записи
   задача не считается закрытой.

Формат записи:

```markdown
## 2026-10-05 — краткая суть одной строкой

**Что сделано**
- по пунктам, человеческим языком, без пересказа диффа

**Почему**
- причина правки: что было не так

**Решено не делать**
- что сознательно не тронули и почему (чтобы следующий не переделывал)
```

Разделы «Почему» и «Решено не делать» важнее списка файлов: диff виден в git,
а намерение — нет.

## Что это за проект

Главное меню веб-игры **The civilization of the sages** с системой аккаунтов:
регистрация/вход, аватарки, друзья с заявками, код-приглашения. Это PWA —
ставится на ПК и телефоны как приложение и работает офлайн. Два режима
данных: локальный (`localStorage` браузера) и общий хаб. Хаб живёт либо на
ПК игрока (`server/serve.mjs` поднимает `/api/*`, данные в
`data/mir-hub.json`), либо на бесплатном хостинге (`hosting/cloudflare/`,
данные в Durable Object) — логика у них общая, `server/hub-core.mjs`.
Выбор адреса — в `initBackend()`: ссылка `?hub=`, сохранённый адрес, вшитый
при сборке `VITE_MIR_HUB`, адрес страницы. При каждом запуске хаб проверяется
первым; локальное хранилище остаётся офлайн-резервом, если ни один хаб не ответил.
`src/data/p2p.js` поднимает WebRTC в фоне как вторичный канал: основной маршрут
аккаунтов и сообщений — хаб, прямой P2P используется как резерв при сбое хаба.
Кнопка «Играть» открывает экран слотов карт: шесть слотов и две вкладки —
«Мастер» и «Игрок», у каждой роли свои слоты (`localStorage`, ключ `mir-world-slots`,
через `src/data/store.js`). Карты делает только Azgaar Fantasy Map Generator
(`vendor/azgaar-fantasy-map-generator/`); собственного генератора и редактора мира в
игре нет. Слот хранит seed, размер (`width`, `height`) и дату. Карта пересоздаётся
Azgaar при каждом открытии, правки Azgaar в слот не попадают. Размер передаётся в адрес
явно: без него карта зависит от ширины окна, и один seed на разных экранах даёт разные
миры. Мастер получает полный редактор Azgaar. Игрок открывает ту же карту с панелями
правки, скрытыми через интерфейс (`PLAYER_CSS` в `src/game/azgaar.js`). Это ограничение
интерфейса, а не защита: прямые действия по карте не блокируются. `mir.html` и APK
вшивают Azgaar в один файл (шаблон `mir-fmg-template`, сборка `scripts/lib/fmg-offline.mjs`);
web/PWA открывает карту из `/fmg/index.html`, и её ресурсы входят в офлайн-кэш.
«Настройки» управляют звуками, громкостью, анимациями, проверкой обновлений
и уведомлениями телефона о новой версии
(новая сборка на сервере — строка «Обновление» под шапкой); профиль умеет
менять никнейм и кадрировать,
масштабировать и поворачивать аватарку. Есть скрытая **панель админа**
(семь быстрых касаний знака игры за 2,8 секунды, `Ctrl+Shift+Alt+A` или адрес с `#admin`):
обзор со сводкой, аккаунты, пароли, дружба, заявки, **журнал событий**,
блокировки аккаунтов, переключатель регистрации и диагностика. Открывается
заводским ключом `owlananaslwo` (он публичный — панель напоминает сменить); на
хабе владелец может задать свой ключ через `MIR_ADMIN_KEY` (env на ПК, секрет
воркера на хостинге) или сменить в панели — ключ хранится в данных хаба.
Пароли и здесь ходят только хешем.

Правило простое: `src/data` знает про данные и сеть, `src/ui` — про
разметку и мелочи интерфейса, `src/main.js` их склеивает. Скрипты и
сервер лежат по папкам и никогда не зависят от рабочего каталога —
для этого есть `scripts/lib/root.mjs`.

## Команды

```bash
npm install
npm run dev      # разработка, localhost:5173
npm run build    # веб-сборка в dist/ + проверка Azgaar/offline-cache
npm run single   # пересобрать автономный mir.html (dist/ не трогает)
npm run fmg:install # зависимости vendored Azgaar (Node ≥24)
npm run fmg:build   # пересобрать public/fmg/ после правок источников
npm run share    # собрать и раздать по сети
npm run serve    # раздать уже собранный dist/
npm run build:exe  # Windows-установщик (нужен csc из .NET Framework)
npm run build:apk  # Android-приложение
npm run apk:doctor # разбор готового MIR.apk (можно указать путь и --verbose)
npm run build:all  # всё сразу
npm run doctor     # диагностика сети и туннелей
npm run host       # выложить игру и хаб на бесплатный хостинг Cloudflare
npm run host:dev   # тот же хостинг локально (workerd), без выкладывания
npm run host:secret  # задать секрет воркера MIR_ADMIN_KEY (панель админа)
npm run host:secrets # список секретов воркера
npm run sounds     # игровые звуки меню из пакета uisfx (набор «Arcade» по умолчанию),
                   # другой набор: npm run sounds -- glass
npm run test:p2p   # проверка прямой связи: два клиента, живой WebRTC
npm run test:hub   # проверка хаба по адресу: аккаунты, друзья, панель, сигналинг
npm run test:worker # адаптер хостинга без сети: хранение и «перезапуск»
npm run test:ui    # mir.html + web: слоты мира, iframe Azgaar (seed/размер), offline, хаб и панель
npm run test:avatar # выбор аватарки: поле выбора файла, выбор, отмена, поздний файл
npm run test:perf  # отзывчивость меню: разбор базы, перерисовки, анимации
npm run test:build # артефакты сборки: ссылки, версия, кэш SW, бюджеты веса
npm run test:spacing # отступы: шкала и совпадение полей однотипных блоков
npm run test:lobby-client # клиент лобби против настоящего хаба: кадры карты,
                   # живой предпросмотр, переподключение (нужен jsdom)
npm run test:realtime # ядро лобби с подменённым временем: уборка, лимиты
npm run skills    # обновить скиллы ИИ-агентов из GitHub (.agents/skills и .claude/skills)
npm run skills:check # только сверить хеши с skills-lock.json
```

`test:hub` принимает адрес: `npm run test:hub -- https://mir.имя.workers.dev`
(без адреса проверяет `http://127.0.0.1:4173`). Гонять его нужно и по хабу
на ПК, и по выложенному — они обязаны вести себя одинаково. `test:worker`
дополняет его там, где по сети ничего не видно: поднимает адаптер хостинга
поверх поддельного хранилища, «перезапускает» Durable Object и проверяет, что
блокировки, настройки и журнал никуда не делись. Сети ему не нужно вовсе.

`test:build` смотрит на уже собранное: сначала `npm run build && npm run single`,
потом проверка. Она отвечает на вопросы, которые иначе всплывают у игрока
чёрным экраном: самодостаточен ли `mir.html`, разбирается ли его скрипт как
обычный (не модульный), совпадает ли версия в разметке с `package.json`,
живы ли ссылки в `dist/index.html` и в списке оболочки service worker, не
вырос ли вес за бюджеты. `test:spacing` не запускает ничего: он читает
`src/style.css` как текст и ловит свои числа в отступах — CSS в проверках
иначе не проверить.

`test:perf` требует свежего `mir.html` и того же jsdom: он считает, сколько
байт разбирается и перерисовывается на одно действие (открытие окна, смена
настройки, обновление связи). Подтормаживание интерфейса ловится именно
здесь, а не в проверках разметки.

`test:p2p` требует запущенного `npm run share` на порту 4300 и
одноразовой установки полифила WebRTC для Node:
`npm i --no-save node-datachannel`. `test:ui` требует свежие `dist/` и
`mir.html` (`npm run build && npm run single`), сервер на
`127.0.0.1:8787` с API и web-статикой (`npm run host:dev` либо `npm run serve`)
и `npm i --no-save jsdom`. Он отдельно открывает веб-бандл в jsdom и проверяет
слоты мира, seed и размер Azgaar в адресе iframe, Escape, ресурсы FMG и offline-маршрут, а
затем проходит UI автономной копии и живого хаба. `test:avatar` работает без
сети и хаба, ему нужен только тот же jsdom: он проверяет `src/ui/avatar.js` —
то самое место, где в APK ломалось добавление аватарки. В обычной сборке этих
зависимостей нет — скрипты нужны только разработчику.

## Скиллы ИИ-агентов

В `.agents/skills/` и `.claude/skills/` лежат одинаковые копии скиллов —
инструкций, по которым ИИ-агент работает с проектом. Источники: `cloudflare/skills`
(хаб, Workers, Durable Objects, производительность) и `anthropics/skills`
(интерфейс — `frontend-design`, темы — `theme-factory`, проверка веб-приложений —
`webapp-testing`). Замок `skills-lock.json` хранит sha256 файла `SKILL.md` на
момент установки: `npm run skills:check` показывает, у каких скиллов источник
ушёл вперёд, `npm run skills` скачивает свежие копии и переписывает замок.
Новый скилл добавляется строкой в список `SOURCES` в `scripts/skills-sync.mjs`.

При правках интерфейса сначала загляните в `frontend-design`, при работе с
хабом и воркером — в `workers-best-practices` и `durable-objects`, при
оптимизации загрузки — в `web-perf`.

## Договорённости

**Стиль.** Тёмная тема, острые углы (никаких скруглений), волосяные линии
`rgba(255,255,255,.08)`, разрядка в подписях капсом, один акцентный цвет
`--accent`. Шрифты Inter (интерфейс) и Manrope (заголовки, логотип).
Новые значения цвета — через переменные в `:root`, а не числами по месту.

**Иконки.** Для интерфейса карты использовать helper `icon()` из
`src/ui/icons.js`: один пак Lucide 1.53.0, SVG 24×24 с контурным штрихом.
Не заменять иконки UI на emoji, шрифтовые глифы или текстовые стрелки.
Печать The civilization of the sages — фирменная эмблема и остаётся исключением;
наборы художественных символов самих карт Azgaar не перекрашивать и не заменять.

**Отступы — только по шкале.** В `gap`, `padding`, `margin` и `inset` стоят
только токены `--sp-*` из `:root` (2, 4, 6, 8, 10, 12, 14, 16, 20, 24, 32);
своё число (7px, 13px, 17px) — ошибка, даже если «так ровнее». Поля одного
компонента задаются общим токеном, а не по месту: `--dialog-pad` — шапка,
тело и вкладки окна; `--panel-pad-x/-y` — шапка, список и подвал панели
друзей; `--pad-x` — сцена, верхняя панель, подвал, тосты; `--row-pad/-gap` —
строки списков; `--box-pad/-gap` — блоки с рамкой. Одно свойство у одного
селектора объявляется ровно один раз: второе объявление молча отменяет
первое, и «поле 18px» превращается в «поле 15px» незаметно для читателя.
Правя вёрстку, смотрите на соседние блоки того же типа: у окна — шапка, тело
и вкладки, у панели друзей — шапка, список и подвал, у строк списка — одни и
те же поля. Если кажется, что нужно «своё» число, скорее всего нужен новый
токен плотности, а не 13px. Проверка — `npm run test:spacing`; она падает на
любом из этих нарушений.

**Высоты кнопок — тоже по шкале.** Высота контрола не получается сама из
полей: мини-кнопка, поле ввода и основная кнопка в одном ряду оказываются
разного роста (было 30 / 45 / 39). Поэтому высота задаётся токенами
`--control-h` (44px — основные: `solid-button`, `.input`, `.ghost-button`,
`.icon-button`), `--control-h-sm` (36px — `.icon-button--sm`, `.profile`,
аватарки рядом) и `--control-h-mini` (36px — `.mini-button`, `.code-box`,
кнопки в строке заявки); на телефоне `--control-h-mini` подтянут до 44px.
Ряды со смешанными контролами (`dialog__actions`, `code-form__row`,
`chat__form`) растягиваются через `align-items: stretch`, а не подгоняются
полями. Длинные подписи кнопок переносятся (`text-align: center`), а не
режутся `nowrap`.

**Никаких заглушек.** Функциональность добавляется только по явной просьбе
владельца — но тогда она обязана быть настоящей и доведённой до конца
(сейчас это аккаунты, аватарки и друзья). Никаких «скоро будет доступно»,
`alert` и ссылок в никуда. Кнопки, про которые не просили («Играть»,
«Настройки»), остаются честно бездейственными.

**Логика хаба — только в `hub-core.mjs` (с его подмодулем `hub-lobby.mjs`).**
Адаптеры (`server/hub.mjs` для ПК, `hosting/cloudflare/worker.js` для
хостинга) знают ровно три вещи: как прочитать запрос, как принять сокет и
куда сложить данные. Бинарные сообщения сокета приходят разными типами
(`ArrayBuffer` у ПК, `Blob` у `workerd`) — адаптер приводит их к байтам до
передачи в ядро; проверка — `npm run test:worker` и `wrangler dev`. Ни одного правила игры — имён,
паролей, дружбы, лимитов — в адаптерах быть не должно, иначе ПК и хостинг
разойдутся молча. Ядро живёт на голых веб-API (`fetch`, `crypto`,
`setTimeout`): `node:*` в нём запрещён — в воркере таких модулей нет.
Меняете ядро — прогоните `npm run test:hub` по обоим адаптерам.

**Связь — в `p2p.js`.** Весь WebRTC (соединения, повторы, сердцебиение,
коды подключения и резервная доставка) живёт только там; `main.js` лишь
спрашивает статус и рисует. Основной маршрут сообщений — хаб; прямой P2P
поднимается вторым и включается при ошибке доставки через хаб. Хаб передаёт
offer/answer/ICE и сообщения-ретрансляции, но не игровую логику. Меняете набор
сигналов — поправьте и `hub.mjs` (`/api/p2p/*`), и `p2p.js`: они обязаны
понимать одно и то же.

**Отзывчивость — часть функциональности.** Меню перерисовывается только
тогда, когда данные действительно изменились: панели и окна сравнивают
разметку с уже нарисованной, разметка аватарок кешируется, а частые
обновления связи (замер задержки P2P) не трогают список друзей. Локальная
база разбирается один раз и живёт в кеше. Анимация открытия окна не должна
проигрываться повторно при обновлении данных. Проверка —
`npm run single && npm run test:perf`.

**Служебная панель.** Её маршруты живут в `hub-core.mjs` (`/api/admin/*`) и
закрыты ключом: без `MIR_ADMIN_KEY` и без смены ключа из панели действует
заводской. Панель не должна светиться в обычном меню, а ключ — попадать в
адрес, в логи и в файлы данных: он передаётся заголовком и хранится только в
памяти вкладки (локально — хешем).

Новое действие панели добавляется в двух местах и только так: правило — в
`hub-core.mjs` (и, если оно работает в офлайн-режиме, зеркально в локальном
бэкенде `store.js`), разметка — в `main.js`. Оба режима обязаны вести себя
одинаково: имя действия, повод и ответ — одни и те же, потому что окно панели
не знает, в каком мире оно работает. Блокировка аккаунта (`user.ban`), журнал
событий (`db.events`, до 300 записей, свежие вперёд) и настройки хаба
(`db.settings`) — часть данных хаба: на ПК они лежат в `data/mir-hub.json`,
на хостинге — в Durable Object, и журнал не должен расти бесконечно.
Пароли, ключ и token'ы в журнал не пишутся — только имена, id и повод.

**Сессия — это вход, а не присутствие.** Закрытие вкладки и обновление
страницы (браузер присылает `beforeunload` и на F5) отмечают «вышел из меню»
(`/api/offline`), но токен устройства при этом не отзывается — иначе игрока
выбрасывало бы из аккаунта после каждой перезагрузки. Токен отзывает только
явный выход (`/api/logout`) и меры владельца (отключение, блокировка, сброс
пароля). Меняете поведение выхода — проверьте оба случая: `npm run test:hub`
(«уход из меню не отзывает сессию») и `npm run test:ui` (перезагрузка через
`beforeunload`, «Выйти» отзывает токен, локальный режим тоже переживает
перезагрузку). И ещё: если хаб не ответил на старте, приложение уходит в
локальный режим, но делает одну тихую повторную попытку — сессия жива, и
игрок должен вернуться в аккаунт сам.

**Логика — в `store.js`.** Всё состояние читайте и меняйте только через его
функции; прямые обращения к `localStorage` из `main.js` запрещены. Пароли —
только хешированные (SHA-256 + соль), в открытом виде не храним, не логируем
и по сети не гоняем (на хаб уходит только хеш). Дублирующая бизнес-логика
хаба в `hub.mjs` должна зеркалить локальный бэкенд `store.js` — меняете
правило в одном месте, меняйте и в другом.

**Сборка — на стороне сборщика, а не на тексте.** `mir.html` собирается
плагином Vite (`scripts/lib/vite-mir.mjs`, хук `generateBundle`), а не правкой
готового `dist/index.html` регулярками: разметка и стили встраиваются там, где
их собирает Rollup, а бандл идёт в формате `iife`, поэтому `import`/`export` в
нём физически не появятся (модульный скрипт не работает по file:// — это
главная причина, по которой однофайловая версия существует; сборка падает,
если синтаксис модуля всё-таки обнаружится). Версия живёт только в
`package.json` и подставляется сборкой (`__APP_VERSION__`, метатег
`mir-version`), имя кэша service worker считается как
`mir-app-<версия>-<хеш сборки>`; отпечаток включает и код, и содержимое `public/`,
список оболочки собирается по факту. Новые обычные ресурсы импортируйте из
`src/`, а не кладите в `public/`. Единственное крупное исключение — полный
vendored Azgaar FMG: исходники в `vendor/azgaar-fantasy-map-generator/`, сборка
в `public/fmg/` (`npm run fmg:build`), фиксированный путь нужен web/PWA и его офлайн-ресурсам.
Тот же исходник второй раз собирается в один HTML для `mir.html` и APK
(`scripts/lib/fmg-offline.mjs`, конфиг `scripts/lib/fmg-offline.config.mjs`):
это вшивка, а не отдельный экспорт. Сгенерированный `public/fmg/` не редактируйте
вручную. `npm run test:build` проверяет бандл, наличие FMG и полное включение
редактора в precache; nested-worker FMG не публикуется, маршрут обслуживает
только корневой worker приложения.

**Сборка обязана объяснять свои ошибки.** Любой сборщик пишет полный
протокол через `scripts/lib/log.mjs` в `logs/<имя>.log`: шаги, размеры,
смещения, хеши и каждую проверку. Проверка формулируется так, чтобы при
провале было видно следствие («Android 11+ отвергнет пакет:
INSTALL_PARSE_FAILED_RESOURCES_ARSC_COMPRESSED»), а не только факт
несовпадения. Новую проверку добавляете — добавляйте и объяснение в поле
`fail`. Самопроверка идёт по **прочитанному с диска файлу**
(`scripts/lib/apk-read.mjs`), а не по переменным в памяти: иначе сборщик
проверяет собственные намерения. Строгие разборщики (`crypto.X509Certificate`,
`openssl`) обязательны там, где на телефоне работает BoringSSL — нестрогие
библиотеки пропускают ошибки, из-за которых Android отказывает в установке.

**WebView в APK сам файл не выберет.** Android намеренно не даёт WebView
системный выбор файла: без `WebChromeClient.onShowFileChooser` клик по
`<input type="file">` не делает вообще ничего — ни окна, ни ошибки, ни
строки в журнале. Поэтому в `classes.dex` два класса: активность и
`MirChromeClient`, который запоминает обещание WebView, открывает
`ACTION_GET_CONTENT` через `FileChooserParams.createIntent()` и отдаёт
результат в `MainActivity.onActivityResult`. Уберёте его — аватарка в APK
снова перестанет добавляться молча; `scripts/lib/apk-audit.mjs` это ловит
(восемь проверок вокруг `onShowFileChooser`). Со своей стороны страница
обязана прикреплять `<input type="file">` к документу до клика и не
признавать отмену по первому фокусу — на телефоне фокус возвращают раньше,
чем заполняется `input.files` (проверяет `npm run test:avatar`).

**Ошибка на телефоне должна быть видна с телефона.** В APK зашиты два
независимых способа: активность ловит исключение в `onCreate` и печатает стек
на экран (плюс `Log.e` с тегом `MIR`), а в страницу вставляется экранный
журнал из `scripts/lib/web-diagnostics.mjs`. Тот журнал пишется на ES5 без
стрелочных функций и шаблонных строк — он обязан выполниться в старом
WebView, который не смог разобрать основной бандл; иначе самый частый случай
(«телефон старый») так и останется чёрным экраном.

**Service worker.** Заготовка лежит в `src/sw.js`, готовый `dist/sw.js`
пишет сборка. Кэширует всё, кроме `/api/*`. Новая версия не перехватывает уже
открытую страницу и не вызывает автоматическую перезагрузку: worker ждёт
закрытия вкладок и активируется при следующем запуске. Имя кэша поднимать
руками не нужно и нельзя: оно состоит из версии и хеша содержимого сборки,
поэтому меняется ровно тогда, когда меняется код, и старый кэш не залипает.
Каждый файл оболочки кладётся отдельно — один недоступный адрес не срывает
установку целиком.

**Обновления — только по кнопке.** О новой сборке приложение узнаёт тремя
независимыми способами: ждущий worker, файл `/mir-build.json` и метка в
разметке `<meta name="mir-build">` — это всё `src/data/update.js`; `main.js`
только рисует строку под шапкой, тост и уведомление. Три правила, которые
нельзя ломать: `skipWaiting` вызывается только по сообщению страницы
(`mir:skip-waiting`) и только из действия игрока; `controllerchange`
перезагружает страницу лишь тогда, когда этого захотел сам игрок; метка
сборки одна на три места (разметка, имя кэша, `const BUILD` в worker) и
`/mir-build.json` никогда не попадает в офлайн-кэш — иначе сравнение
выродится в «старое со старым». Уведомления телефона — настройка игрока
(`notify`, по умолчанию выключена), разрешение спрашивается только по его
действию; выбор передаётся worker'у сообщением, потому что localStorage ему
не виден. Открытая с диска копия (`mir.html`, `.apk`, `.exe`) проверять
обновления не может — и должна говорить об этом прямо, а не «проверено
только что».

**Артефакты пересобирать.** После правок в `index.html` или исходниках игры в
`src/` обязательно `npm run build && npm run single && npm run test:build`, иначе
`mir.html` разойдётся с исходниками. После правок vendored Azgaar сначала
выполните `npm run fmg:build`, затем `npm run build && npm run single &&
npm run test:build`; веб-каталог и offline-precache должны соответствовать
одному source snapshot, и `mir.html` (он вшивает Azgaar из того же исходника при `npm run single`). Если
поменялась раскладка — обновите `preview.svg`.

**Бренд и тексты.** Интерфейс русский, отображаемое имя продукта —
**The civilization of the sages**, ключевая фраза — «Мудрость создаёт миры.»
Полное имя остаётся в игре, на Windows и в метаданных; короткий системный ярлык
`Sages` используется в PWA и Android. В шапке и заголовке имя разбито на две
строки (`The civilization` / `of the sages`). `MIR` оставляем для legacy-файлов,
пакета `com.mir.game`, хаба, storage-ключей, журнала Android и старого seed
процедурной карты (он сохраняет прежнюю карту при пустом seed) — их не
переименовывать без отдельной миграции. Атрибуцию Azgaar и лицензии не удалять.

**Адаптив.** Проверяйте диапазон 320–2560px. Контрольные точки: 1180 (сужается
панель друзей), 1000 (прячется текст профиля), 860 (панель уходит вниз лентой),
680 (прячется название в шапке), `max-height: 620px` (мельчает заголовок).

**Доступность.** У каждой кнопки доступное имя, видимый фокус, логичный порядок
табуляции, ориентиры `header/nav/main/aside/footer`, одна `h1` на страницу.

## Cloudflare

When interacting with Cloudflare, use the cf CLI unless the project has a Wrangler configuration file. (This project has `wrangler.toml`, so prefer Wrangler for deploys; use `cf` for general Cloudflare API tasks.)
