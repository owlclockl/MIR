## 2026-10-05 — аккаунты, друзья и аватарки

**Что сделано**

По явной просьбе владельца меню перестало быть только интерфейсом: появился
настоящий клиентский функционал, без единой заглушки.

- **Аккаунты** (`src/store.js`). Регистрация и вход в модальном окне: валидация
  имени (3–16, без пробелов), пароль от 6 символов, пароль хранится как
  SHA-256 с индивидуальной солью — в открытом виде нигде не светится.
  Сессия переживает перезапуск, выход «гасит» присутствие. Есть смена пароля
  (с проверкой текущего). Всё в `localStorage` под ключами `mir:*`.
- **Аватарки** (`src/avatar.js`). Загрузка PNG/JPEG/WebP/GIF до 8 МБ,
  центр-кадрирование и уменьшение до 96×96 на canvas, предпросмотр перед
  сохранением. Без загруженной картинки — инициалы на цвете, вычисленном
  из имени (детерминированно, у всех одинаково).
- **Друзья**. Заявки по имени: поиск по аккаунтам, состояния «уже в друзьях»
  / «заявка отправлена» / «принять». Встречная заявка превращается в дружбу
  сразу. Входящие заявки — блоком в панели с бейджем на кнопке «+».
  Удаление друга — с подтверждением, действует в обе стороны.
- **Код-приглашения**. У каждого аккаунта код `XXXX-XXXX` (алфавит без
  похожих символов). Друг вводит его — дружба мгновенная и взаимная, без
  заявки. Код можно скопировать (с запасным путём без `navigator.clipboard`)
  и сменить — старый при этом умирает.
- **Присутствие честное**: «в сети» = активная сессия + свежий heartbeat
  (30 с, TTL 90 с). Закрыл вкладку — `beforeunload` гасит статус, аварийный
  вылет доедает TTL. Вкладки синхронизируются событием `storage`.
- **Интерфейс**: модальные окна (вход/регистрация, добавить друга, профиль,
  карточка друга, предпросмотр аватарки, подтверждение) с ловушкой фокуса,
  Esc и закрытием по фону; тосты об успехе/ошибке; пустые состояния для
  гостя и для пустого списка. В гостевом режиме в шапке — кнопка «Войти»,
  панель друзей предлагает создать аккаунт.
- **Сборка однофайла переписана.** `build-single.mjs` больше не встраивает
  `main.js` текстом (проект стал модульным — `store.js`, `avatar.js`),
  а прогоняет `vite build` и инлайнит готовые JS/CSS из `dist/`.
- Версия поднята до 0.2.0, `preview.svg` обновлён под новое наполнение.

**Почему**

Запрос владельца: «полноценная система аккаунтов, приглашения друзей,
аватарки». Раз функциональность заказана, правило «никаких заглушек»
перевернуто: каждая кнопка теперь делает настоящее действие.

**Как проверялось**

- 36 юнит-проверок слоя данных в Node (auth => заявки => коды => аватар =>
  смена пароля; нашли и поймали баг: новая сессия не гасила присутствие
  предыдущей).
- 42 DOM-интеграционные проверки UI на jsdom: весь путь «гость →
  регистрация → заявка → принятие → дружба по коду → профиль → выход →
  вход по новому паролю».
- `vite build` и `npm run single` собираются, dev-сервер отдаёт все модули.

**Решено не делать**

- **Бэкенд не появлялся** — это статичный фронтенд, сервера в проекте нет.
  Данные живут в браузере: «друзья» — аккаунты, созданные на том же
  устройстве (или в том же браузере). Код-приглашение честно работает при
  передаче в таком радиусе. Если понадобится сетевая игра — это отдельная
  эпопея с сервером.
- **SHA-256 — не защита от настоящего взлома.** Это гигиена (пароль не
  лежит открыто), а не гарантия: localStorage доступен любому скрипту на
  странице. Для защищённого хранения нужен сервер; зафиксировано честно
  в тексте окна входа («всё хранится локально»).
- **«Играть» и шестерёнка настроек остались без обработчиков.** Про них
  не просили; правило «функциональность — только по явному запросу» снимает
  запрет только на заказанное.
- **Статус «В игре» не назначается никому** — игры пока нет, а присутствие
  честное. Карта состояний в коде оставлена на будущее.
- **Никакого редактора кадрирования** (drag/zoom): кроп по центру решает
  95% случаев, полноценный редактор — отдельный компонент, когда понадобится.

## 2026-10-05 — журнал изменений и сервер для показа друзьям

**Что сделано**

- Заведён этот журнал и `AGENTS.md` — файл, который ИИ-агенты читают
  автоматически перед работой. В нём зафиксированы правила проекта:
  стиль, запрет на заглушки, контрольные точки адаптива, обязательная
  пересборка `mir.html`.
- Добавлен `serve.mjs` — статический сервер без единой зависимости, только
  встроенные модули Node. При старте печатает адрес для этого компьютера и
  адреса для друзей в той же сети Wi-Fi.
- Новые команды: `npm run share` (собрать и раздать), `npm run serve`
  (раздать готовый `dist/`), `npm run share:public` (плюс попытка поднять
  публичную ссылку через `npx localtunnel`).

**Почему**

- История проекта жила только в сообщениях коммитов и в переписке: каждый
  следующий заход начинался с археологии. Журнал плюс `AGENTS.md` решают это.
- Показать работу друзьям раньше можно было только через `npm run dev`, то есть
  с дев-сервером Vite и HMR — это не то, что стоит отдавать на проверку.

**Что внутри сервера**

- Защита от выхода за пределы каталога: проверены `..`, `%2e%2e`, `..%2f`
  и вложенные варианты — все дают 404 без утечки содержимого.
- gzip для текстовых файлов (css ужимается с 12.3 КБ до 3.3 КБ), ETag и 304,
  «вечный» кэш для файлов из `assets/` с хешем в имени, `nosniff`.
- Если порт занят — берётся следующий свободный, и в баннере печатается
  именно тот номер, который реально слушается.
- Корректное завершение по Ctrl+C; падение туннеля не роняет локальный сервер.

**Решено не делать**

- **Не стали ставить зависимости ради сервера.** `express`/`serve` потянули бы
  десятки пакетов в проект, где сейчас одна зависимость — Vite.
- **Публичная ссылка не проверена в деле.** Код для `--public` написан и
  обрабатывает отказы, но в песочнице, где он писался, выход в интернет закрыт,
  поэтому живьём туннель не поднимался. У `localtunnel` есть известная
  особенность: первому посетителю показывается страница с запросом пароля
  (это внешний IP владельца). Для постоянной ссылки без этих плясок надёжнее
  GitHub Pages — см. README.
- **Имя файла `mir.html` и `"name": "mir-game-menu"` не менялись.** Это
  внутренние идентификаторы, завязанные на сборку и имя репозитория, а не
  отображаемое название игры.

## 2026-10-05 — переименование в «The civilization of the sages» и переработка интерфейса

**Что сделано**

Название заменено везде, где видно пользователю: заголовок вкладки, логотип в
шапке, заголовок на экране, подвал. Имя разбито на две строки
(`The civilization` / `of the sages`), вместо буквенной марки «M» — геометрический
знак (окружность с точкой).

Вёрстка:

- Каркас переведён с абсолютного позиционирования на CSS Grid. Панель друзей
  стала колонкой во всю высоту, шапка — только над сценой. Благодаря этому
  центр кнопки «Играть» совпал с центром заголовка: раньше они расходились
  на 150 px, потому что кнопка центрировалась по всему экрану, а заголовок —
  по области без правой панели.
- Убраны «магические числа»: `margin-right: 286px`, `right: 306px`,
  `calc(100vh - 76px - 178px)`. Размеры живут в переменных `--bar-h`, `--rail-w`.
- Иконка настроек рисовала мусор — её SVG-путь был повреждён. Все иконки
  заменены на корректные контуры Lucide.
- Типографическая шкала 10–15 px вместо 8–11 px: подпись в подвале была 8 px и
  практически не читалась.
- Статусы друзей теперь различаются видом точки (в игре — залитая, в меню —
  контурная, не в сети — тёмная) вместо хрупкого правила `:nth-child(2)`.
- Точки статуса прижаты к правому краю строки: не хватало `flex: 1` у текста.
- Риска под кнопкой «Играть» в покое приглушена — раньше смотрелась как
  случайный артефакт, — и разгорается при наведении.
- Добавлены `100dvh` и safe-area.

**Почему**

Интерфейс был собран на абсолютном позиционировании с жёстко вбитыми числами:
любое изменение ширины панели требовало править четыре места. Плюс копились
мелкие дефекты — сломанная иконка, нечитаемый мелкий текст, рассинхрон центров.

**Как проверялось**

Настоящий Chromium: раскладка на 10 разрешениях от 320 до 2560 px (заголовок
нигде не переносится и не переполняется), состояния наведения, обход с
клавиатуры, продакшн-сборка и автономный `mir.html`, открытый по `file://`.

**Решено не делать**

- **Подписи в заголовке оставлены прежними** — «Тактический протокол» и
  «Тишина — тоже оружие». Это текст от старого названия, и с «цивилизацией
  мудрецов» он звучит разнородно, но придумывать новый за владельца проекта
  было бы самодеятельностью. Вопрос открыт.
- **Функциональность не добавлялась.** Всплывающие уведомления «скоро будет
  доступно» удалены вместе с `notify()` и всеми обработчиками событий: в JS
  не осталось ни одного `addEventListener`. Кнопки остались просто кнопками —
  это явное требование владельца.

## 2026-10-05 — первая версия

Минималистичное главное меню под названием MIR: шапка с кнопкой «Играть»,
экран с крупным заголовком, панель друзей справа, подвал. Сборка на Vite плюс
скрипт `build-single.mjs`, склеивающий всё в один файл `mir.html`.
